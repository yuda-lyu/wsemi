- 規則:
  1. (IR-01,契約本文在 `src/lowerFind.mjs` 檔頭) IR 節點恰六種: `and{a}`、`or{a}`(n 元,至少 2 項,單項已展開,同型已攤平,零項不產生)、`cmp{c,op,v,p}`(op: eq ne gt gte lt lte;v: string/number/Date,非 null、非布林)、`bool{c,op,v,p}`(v: 布林;語意為 SQL 三值: NULL 列不命中任何布林比較,含 ne)、`null{c,not,p}`(IS [NOT] NULL)、`in{c,vs,not,p}`(vs 為純量陣列,元素可為布林,不含 null;`not=false` 且 `vs=[]` = **恆假**,結果集為空;`not=true` 且 `vs=[]` 不產生)。無條件 = `null`。`c` 為欄名(已通過 `opt.checkColumn`);`p` 為葉節點來源路徑(如 `find.$or[0].age.$gt`),僅供診斷、不參與語意、快取鍵須忽略,`and/or` 不帶 `p`。
  2. (IR-02,語意) `{ c: null }`、`$eq:null` → `null`;`$ne:null` → `null not`;其餘 `$ne`/`$nin` 為三值邏輯(不命中 NULL 列);同欄多運算子與多欄鍵為隱含 AND(攤平);`$and/$or` → `and/or`;單項展開;**`lowerFind` 不因方言上限(如 `maxList`)限制攤平寬度**(巢狀 `$or` 2×600 攤平為 1200 項),重新分組(平衡二分、深度上限)是發射器之責;`in{vs:[]}` 恆假,發射器是否引用欄位(因而回報不存在之欄名)自決,**不得影響結果集**。
  3. (IR-03,opt) `opt.maxParams` **必填**(正數或 `Infinity`;核心不預設任何方言上限;以屬性存取讀取 `opt` 自有可列舉屬性〔自有存取器會被呼叫;繼承值與不可列舉屬性不生效;`opt` 為呼叫端程式設定而非輸入資料,不防其存取器——外審 sol F07 指出原稿稱[只讀自有資料屬性]與搬入碼之 `propertyIsEnumerable` + `o[k]` 不符,以行為不變為準更正文件並以測試鎖定〕;缺漏 `throw Error('lowerFind: opt.maxParams is required (use Infinity for no limit)')`);計數契約: `cmp` 計 1、`in` 每元素計 1、`bool`/`null`/空 `in` 計 0,超過即 `throw`(訊息 `invalid find: too many bound parameters (> N) at [路徑]`,路徑指向越限元素);不綁定參數之後端(內嵌轉義、記憶體查詢)傳 `Infinity`。`opt.checkColumn(name)`: 方言專屬欄名檢核,回 `''` 通過、其餘為拒收原因;只對欄名鍵呼叫(不含 `$and/$or`);非函數或繼承值不生效。
  4. (IR-04,錯誤) 一律同步 `throw Error('invalid find: <原因> at [<路徑>]')`,與 `cvOrmFind` 同格式,**不回顯值**(訊息與路徑經控制字元取代與限長)。
  5. (IR-05,堅固性) 輸出皆為 null 原型節點;陣列以 `defineProperty` 附加(不用 `push`/索引指派——`Array.prototype` 數字索引 setter 存在時元素會被吞掉而條件變寬);`Object.prototype` 汙染 IR 欄位名(`t c op v vs not a p`)不生效。
  6. (IR-06,純 JS) 零 import、不用 Node API、不含任何資料庫/建構器/驅動名稱(測試掃描檔案文字)、`src/` 內無 BigInt 字面值(R-FIND-01 規則 15)、可在 `vm` 空領域載入執行(`test/tools/srcBundle.mjs`)。
  7. (IR-07,行為不變) 自 pg 1.0.35 `src/lowerFind.mjs` 搬入,**邏輯與輸出逐字不變**,唯一差異是匯出形式(具名 `export function` → 預設匯出)、`eqNode` 改名 `lowerFindEq` 分檔,及檔頭/JSDoc 文字.實測(2026-10-21,一次性腳本 `tmp/cmpPgSnap.mjs`、`tmp/cmpPgSem.mjs`,pg repo 唯讀): ①pg `tmp/cases/ir-snapshots.json`(119 筆,3 MB,wsemi 共用案例表 77 + pg 自有 top/logic 42)——該檔由加葉節點 `p` 欄**之前**的原型產生(不含 `p`),**去掉 `p` 後 119/119 逐筆相等**(含 `p` 時只有 6 筆無葉節點者相等,屬預期);②pg 現行 `test/tools/ir-snapshots.json`(73 筆,含 `p`)與 wsemi `_lowerFindSnapshots` **deepEqual**;③pg `test/tools/irSemantics.mjs` 之 `SEMANTICS` 40 筆與 `SEM_ROWS` 之 find/ir/hits 與 wsemi `_lowerFindCases` 同 `id` 者逐筆相等(wsemi 增至 85 筆).**表示法差異僅一處**: wsemi 的 `norm` 以 `{ $negZero: true }` 標記 -0(JSON 會把 -0 轉成 0,外審 minimax F4;`-0` 為 `cvOrmFind` 接受之純量),故共用案例表 `E21`(`age: -0`)之快照與 pg 現行快照在該值上表示法不同(pg 為 `0`),IR 本體(`lowerFind` 輸出)相同;超過 2^53 之數值經 JSON 往返不失真(雙精度之最短表示可還原,審查者所稱[9007199254740993 失真]在輸入時即已是 ...992)。
  8. (IR-08,`lowerFindEq`) `lowerFindEq(c, v)` 回單欄等值節點: 布林 → `bool eq`,其餘 → `cmp eq`(`v` 不再檢核,含 ±Infinity——float8 主鍵可為 ±Infinity,由呼叫端之主鍵檢核擔保純量);`p` 為 `find.<欄名>`(欄名限 30 字元並取代控制字元);節點為 null 原型;與同一值經 `lowerFind` 所得 IR 相同(`selectByPk` 與 `select` 共用快取鍵)。
  9. (IR-09,契約案例表,取代「3 MB 快照原樣搬入」) 套件隨附三層契約,增量見下:
     - 層 1 `semantics`(手寫,每筆 `{ id, node, find(), ir, hits }`): 以固定 6 列 `seed()`(id 數字主鍵,欄 `s` 文字、`n` 整數、`b` 布林、`d` 時間,含 NULL 列)依 SQL 三值邏輯**手推**命中集合 `hits`;涵蓋六節點、各運算子、Date、`$..$` 字面值、布林三值、空 `in`、單項展開、同型攤平、隱含 AND、`and` 在 `or` 內、欄鍵與 `$or` 並列、無條件。測試: (a) `lowerFind(cvOrmFind(find()))` 之正規化 IR = `ir`;(b) 以 `irEval` 對 `rows` 求 `ir` 之命中集合 = `hits`(表內部一致,與實作無關);(c) 六種節點皆被涵蓋。reladb/mdb 發射器遷移時以此表獨立對拍: 對 `seed()` 建表,逐筆以 `ir` 發射,命中集合須 = `hits`。
     - 層 2 `snapshots`(產生): `_cvOrmFindCases` 中 `cvOrmFind` 接受且 IR 序列化 ≤ 20000 字元者之 IR(Date 以 `{ $date: 毫秒 }`);測試: 現行 `lowerFind` 輸出逐筆 = 快照(差異即契約變更,須有意識重產並審 diff);**語意由獨立路徑守住**: `irEval(IR, seed())` = 該案 `ids.sql`(不靠快照本身),另以 400 棵種子化隨機條件對 `ormFindRef`(find 層參考比對器)與 `irEval(lowerFind(...))` 做差分。大型 `$in`(H07 5000 元素、H28 10000、H13 等)不入快照,改由性質測試守住(計數、攤平寬度、深度)。
     - 層 3 檔頭文字契約(IR-01~IR-05)與各節點之 ANSI 骨架示意(`c <op> ?`、`c IS [NOT] NULL`、`c [NOT] IN (?, …)`、恆假);**方言骨架(如 pg 之 `"s" = $1`、`IS TRUE`)不屬契約**,各後端自表(pg 之 `irSemantics.mjs` 以同一組 `id` 掛接 `where`/`values`)。
  10. (IR-10,不納入) `groupIr(ir, nFlat)`(reladb `cvGroup` 之平衡二分)不隨本次搬入(方案 §3.9「可同置」為選項;該分組與 reladb 之 `maxList`/表別名差異耦合,待第②步 reladb 採用時再決定);`order`/`limit`/寫入走訪不屬本層。
  11. (IR-11,前提、值域與方言承擔,外審後補) ①**前提**: `lowerFind` 之輸入須為 `cvOrmFind` 之複本;非複本之輸入不保證節點形狀(空 `$and`/`$or` 得零項 `and`/`or` 節點、空運算子物件被略過而視同無條件——外審 minimax F1 實測;縱深防禦僅限白名單外運算子),此類輸入經 `cvOrmFind` 不可達(測試核對 `cvOrmFind` 拒收 `{$and:[]}` `{$or:[]}` `{a:{}}` `{$and:1}` `{$or:[1]}` `{$and:[{}]}`);是否加零項防護屬行為變更,待主控裁示。②**值域與比較約定**(`_lowerFindCases` 檔頭): IR 值恆為 string/有限 number(含 -0)/boolean/有效 Date,欄位型別不在 IR 內;比較以 `columns` 宣告之欄型為準——數值格式字串對 integer 欄先轉數字(同共用案例表 `ids.sql` 約定),不可轉換者不命中或由型別化後端拒收(案標 `schema: true`),Date 以毫秒瞬間比較,字串順序比較依 collation(`hits: null`,只驗 IR)。③**方言承擔項**(不在 IR,不屬對拍範圍): schema 型別化與值正規化(reladb `chkScalar` 等,正規化後之值才是交給發射器之值)、主鍵正規化、欄名解析與存在性、空 `in` 是否引用欄位、and/or 重新分組、bool 字面值與各 op 寫法、識別字引用/參數標記/參數上限、型別化階段之錯誤訊息。④**掛接協定**: 方言端(pg `irSemantics.mjs` 之 `where`/`values`)以 `semantics` 之 `id` 為鍵,測試斷言每個方言 id 存在於 wsemi 表、wsemi 表每個 id 有骨架或明列免除、方言端不另存 find/ir/hits 之副本(外審 minimax F6、sol:兩張複製表無自動掛接);pg 改 import 時由 pg 批落實。
