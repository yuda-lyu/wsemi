## R-TIMER-RELEASE-01 回傳事件物件且持有重複計時器者須可釋放

- 規則:
  1. 回傳事件物件(evem)且由實例持有重複計時器(setInterval)之模組,須提供公開之 `ev.clear` 釋放:清除計時器、取消已排定而未發出之事件計時器,其後不再發出事件,可重複呼叫不拋錯.內部骨架 `_detector` 用 `dispose`,不對外.
  2. 計時器為惰性建立者(如 alive 之 trigger 會重建偵測 interval),釋放須為終態:其後之觸發不建立計時器、不發事件,需重新偵測者另建實例.否則停止後才到之觸發會再撐住行程.
  3. 釋放途中可能由監聽器呼叫(派發中重入),逐筆派發之迴圈每次派發後須檢查已釋放並立即停止.
  4. 釋放本身不發事件;使用端需補發者由回傳值提供(alive.clear 回傳已發出 enter 且尚未 leave 之 `[{ key, data }]`),回傳值與同族不同時須於 JSDoc 寫明.
- 盤點指令: `git grep -l "evem()" -- src`,對所得各檔以 `git grep -n -E "setInterval\(|ev\.(clear|dispose|off)\s*=" -- <檔>` 比對有無釋放.

## R-PM-SETTLE-01 以呼叫端函數或 Promise 之結果決定流程者:必定 settle、不產生未處理之 rejection/例外、佇列必定續行、失敗路徑必清理且可重試

- 單一擁有者: 任務結果正規化 `src/pmConvertResolve.mjs`(即 pm2resolve);`{ state, msg }` → resolve/reject `src/_pmSettleByState.mjs`(內部,不進 index);呼叫端先行產生之 Promise 陣列之預先觀察 `src/_pmMarkHandled.mjs`(內部;2026-10-30 run01 第 181 項起**以品牌判定**:直接以載入時之 `Promise.prototype.then` 執行,非原生 Promise 者於 then 之品牌檢查即拋而忽略〔不讀屬性、不觸發 Proxy 陷阱、不呼叫一般 thenable 之 then〕;跨 realm 與原型為 null 之原生 Promise 亦標記〔原以 instanceof 判定而漏標〕;原型為 null 者無 then 非 thenable,pmSeries/pmMap 依原值交出;原始值直接略過,`util.types.isPromise` 可用時先預檢〔非 Promise 者不進 then,免每次建例外:10 萬個一般值約 296ms→0.4ms,`run01-evidence/probe-pmh-perf.mjs`〕;測試 `test/_pmMarkHandled.test.mjs`,有 util 與無 util 兩種環境);容器於進入時取值 `src/_pmReadItems.mjs`(內部,規則 17);Promise 判定 `src/ispm.mjs`.
- 規則:
  1. 呼叫端函數之任何結果(同步回傳任意值、同步拋出任意值含 null/undefined、Promise resolve/reject 任意值含讀取即拋錯者)使回傳之 Promise 必定 settle;唯永不 settle 之 Promise 或永不呼叫回呼之 thenable 例外(依原生語意等待,需逾時者以 pmTimeout 包裝,JSDoc 載明).
  2. 不得產生 unhandledRejection 或 uncaughtException;檢查或分類結果值之讀取一律在 try 內或交由原生 Promise 機制;計時器回呼與事件監聽器內不得有可拋出之未保護呼叫;記錄與清理本身亦不得拋出(記錄包 try).明文例外: 文件契約為「回調拋錯不攔截、成為未捕捉例外」之串流回調,經 `src/_callUser.mjs` 承接後以 `queueMicrotask` 原樣重拋(R-EXEC-FAIL-01 規則 12)——此為兌現契約之刻意重拋,不得改為吞掉.
  3. 佇列類之後續任務必定執行;狀態復原(cb、running、state、lock)在任務結束之單一出口.
  4. 佇列類之任務結果經 pm2resolve 正規化;`{ state, msg }` 之對應經 `_pmSettleByState`,取消一律以 `{ reason: 'cancelled' }` 傳出;非佇列類以原生機制承接(`new Promise((resolve) => resolve(fn()))`),不以 ispm 分支手寫 then/catch;掛載 then 一律單次 `then(onS, onR)`(不用 `then().catch()`,覆寫 catch 之子類別與 then 回傳 undefined 之 thenable 會失效).
  5. 失敗路徑之清理(計時器、DOM 臨時元素、lock、載入標記)於成功與失敗皆執行,且復原為可重試狀態;清理不得覆蓋原錯誤(清理包 try).
  6. 回呼(如 pmHook 之 cb)拋錯以該錯誤 reject,不得懸置.
  7. 取消慣例不變: `{ reason: 'cancelled' }` 之拒絕值 → pmConvertResolve 為 `{ state: 'cancelled', msg: '' }`;同步拋出之值不判取消;讀取 reason 拋錯者為 error 且 msg 為原值.
  8. ispm 對任何輸入回傳布林值(讀取即拋錯之值回 false).
  9. 持有呼叫端先行產生之 Promise 而延後取用者(pmSeries、pmMap 未給 fun),於進入時即標記已處理;只對原生 Promise 以 `Promise.prototype.then.call(v, undefined, () => {})` 為之,不呼叫一般 thenable 之 then.
  10. 不回傳 Promise 之任務排程者(debounce、pmDebounce、setIntervalHp、setTimeoutHp)之任務失敗以 console.log 記錄(記錄包 try),不外拋.
  11.(2026-10-16 增訂,N12/D29)單一飛行之快取(cache.get)於呼叫 fun **之前**建立並保存本次執行之 Promise(以 `new Promise` 取得 resolve/reject 之參照,run 之結果經單次 `then(resolve, reject)` 轉交),本次執行者 await 所保存之參照(不可 await 可能已被 finally 清回 null 之欄位),等待者於判定當下取用 d.pm: fun 內(含同步階段)呼叫同 key 之 get 共用本次執行而不重複執行;fun 同步拋錯與 async reject 同樣於結束後清除執行中狀態,下次 get 重新執行,clear、過期後亦重新執行(修前同步拋錯使該 key 永久卡死).fun 等待同 key 之 get 之結果為互等而永不 settle(設計限制,JSDoc 載明).
  12.(2026-10-16 增訂,N14、裁示 5 U2)pmThrottle 之任務非函數時不排入(不取消已排入者),回傳之 Promise 以字串 `'fun is not a function'` reject(原回 undefined,與 `@returns` 矛盾);pmQueue 維持現行: 照常排入,輪到時以同一字串 reject(takeLast 下非函數為最後一筆時其前之任務照常被取消);其餘入口維持現行約定並各自寫入 JSDoc(pmDebounce/debounce 回 undefined 並記錄、setIntervalHp/setTimeoutHp 每次到期記錄、pmConvertResolve 建立時同步拋出、pmHook/pmHookReject 回 null、cache.set 視為回傳 undefined 之空函數、cacheBd.get 以 TypeError reject 而 getFromCache 輪詢至 nMax、waitFun reject 字串、pmInvResolve 之 pm 非 Promise 時同步拋出),且 `@returns` 之型別與實回相符(N16: pmConvertResolve、pmHook、pmHookReject 實回 Function,pmHook 另可回 null;pmInvResolve 實為 resolve msg 本身).
