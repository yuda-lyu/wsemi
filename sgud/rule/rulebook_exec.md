## R-EXEC-FAIL-01 執行外部程序之失敗回報:字串或結果物件、不含參數與環境變數之值、不崩潰

- 單一擁有者: `src/_execSpawnError.mjs`(`execSpawnError(err, { cwd }) → { code, message }`,內部模組不進 index);使用端 `src/execProcess.mjs`、`src/execCli.mjs`、`src/execCliSession.mjs`(`src/execCliJsonRpc.mjs` 經 execCliSession).命令解析與批次檔存在 `src/execCliCore.mjs`(`resolveCommand`、`whereList`、`isFileFollowLink`、`isFileStat`、`buildSpawnArgs(command, args, { cwd, env })`).呼叫端串流回調之呼叫點 `src/_callUser.mjs`(內部).入口讀取呼叫端輸入失敗之訊息 `src/_execThrownMsg.mjs`(內部,2026-10-16;四函數之入口 catch 共用).
- 規則:
  1. 無法啟動子進程之錯誤(spawn 同步拋錯、`'error'` 事件、啟動前之例外)一律經 `execSpawnError` 取 code 與 message;不得直接 reject 或回報 node 之 Error 物件,不得讀 `spawnargs`(非同步錯誤所附之完整參數陣列,exec 模式為整條指令列)、`cmd`.有 errno 之系統錯誤 message 原樣(`spawn <執行檔> <碼>`);無 errno 之參數檢查錯誤去除 `. Received 值` 尾段(node 以 inspect 帶出參數或環境變數之值).
  2. 格式: execProcess reject `spawn[碼]:\n訊息`;execCli、execCliSession、execCliJsonRpc 之 error 為 `碼: 訊息`(JsonRpc 另加 `method: ` 前綴);execProcessKillPid reject `pid[N] kill failed: 訊息`.其餘失敗字串(`code[N]`、`timeout[Nms]`、`Exit code N`、`TIMEOUT after`…)只含子程序輸出,不另加參數.
  3. `'error'` 監聽須於存取子進程之 stdout、stderr、stdin 前掛上;stdio 為 undefined 時(node 對 EMFILE、ENFILE 不建立 stdio 即於 nextTick 發出 `'error'`)不得存取.
  4. execCli 系列之 `buildSpawnArgs` 與 `spawn` 須在同一 try 內;execCli 之同步錯誤以結果物件回報(`ok:false`、`code:null`、`pid:undefined` 同 ENOENT、attempts 計 1)且不重試(模組層 WeakSet `kNoRetry`,不擴充對外欄位).
  5. 輸入檢查失敗不同步 throw:execProcess 之 args 須為陣列或字串,空陣列與空字串代表無參數,其餘型別 reject `args is not an array or string`(不帶值);spawn 模式 prog 含引號 reject 說明字串.
  6. Windows 下命令解析不呼叫外部程式(where.exe 之輸出為系統字碼頁,以 utf-8 解碼時非 ASCII 路徑成亂碼):未帶副檔名者依 where 之語意(本進程 cwd → 本進程 PATH;逐目錄先原名後 PATHEXT,名稱含 `.` 亦補);只給檔名之 `.cmd`/`.bat` 依 cmd.exe 之語意(子進程 cwd,子進程 env 有 NoDefaultCurrentDirectoryInExePath 時不搜 → 子進程 env 之 PATH,不補副檔名);含目錄之相對路徑以子進程 cwd 為基準;cwd 為相對路徑時先 `path.resolve`;執行檔與批次檔之存在一律跟隨連結判定(不用以 lstat 判定且連結為 false 之 `fsIsFile`:搜尋用 `isFileFollowLink`,stat 失敗而 lstat 為連結者亦為候選以涵蓋 App Execution Alias;批次檔存在用 `isFileStat`);`.cmd`/`.bat` 查無者不交 cmd.exe,拋與 node 同形之 ENOENT(`spawn <命令> ENOENT`),由呼叫端之同步 catch 回報.
  7. cwd 不存在或非資料夾所致之 ENOENT,訊息改指 cwd(`cwd is not an existing folder: <cwd>`),碼不變;由 `execSpawnError(err, { cwd })` 以 `fs.statSync(cwd).isDirectory()` 判定(跟隨連結,有效之 junction 不改寫;只在 stat 為 ENOENT/ENOTDIR 時視為無效),呼叫端兩路(同步 catch、`'error'`)皆傳 cwd.(2026-10-30 run01,第 179 項)`execProcess` 增 `opt.cwd`(同 execCli:非空字串才採用,否則為本進程之工作目錄;三種模式皆傳給 spawn/exec/execFile),兩路皆傳 cwd,reject 為 `spawn[ENOENT]:\ncwd is not an existing folder: <cwd>`(onTrace 之 settle 為 reason `'spawn'`);Node 對不存在之 cwd 一律經 `'error'` 事件回報(實測三模式皆然),同步 catch 之傳遞為防禦(變異 E6 存活,等價).測試 `test/execProcess.test.mjs`〈execProcess opt.cwd〉.包裝字串之 cwd 不拆包(R-WRAPPER-01 規則 3,同 execCli;node 拒收為 `spawn[ERR_INVALID_ARG_TYPE]`).**未實測之疑點(子代理審查第 3 條,待裁示)**: POSIX 以檔案為 cwd 時 Node 可能回 ENOTDIR(非 ENOENT,且為同步拋出),`_execSpawnError` 只改寫 ENOENT,故訊息不指 cwd(execCli 同);本機僅 Windows,未改.
  8. 子進程環境變數物件之建立(`buildSpawnEnv`)與 buildSpawnArgs、spawn 在同一 try 內;buildSpawnArgs 收子進程 env 以依其 PATH 與旗標解析只給檔名之批次檔.
  9. execCli 之 pid 契約:未能啟動者 code 為 null 且帶 pid 鍵、值為 undefined;已啟動者帶 pid 數值;command 無效者不啟動、attempts 0、不帶 pid 鍵.execCliSession 之未啟動 pid 為 null(既有公開契約).
  10. execCliJsonRpc 之 errorType 依「子進程是否曾啟動」判定:未啟動(session pid 為 null)一律 notfound,不以錯誤字樣判定;逾時 timeout;已啟動後結束 exit.requests 為空陣列(預設值)而子進程未啟動者亦 notfound(2026-10-16 外審 opus F07,原回 ok:true).
  11. 自訂 validate 以原生 Promise 承接:同步拋錯與 reject 視同驗證失敗(error 恰為 `OUTPUT_VALIDATION_FAILED`,stderr 前綴 `validate threw: <訊息>`;以布林旗標判定是否拋錯,拋出之值可為 null/undefined;訊息取 getErrorMessage,為空退 `_errToStr`,截斷至 500 字元);回傳 Promise 者以其 resolve 值判定;回傳之 Promise 不受 timeoutMs 約束,永不落定者依原生語意等待(JSDoc 載明;同 R-PM-SETTLE-01 規則 1 之例外).
  12. 呼叫端之串流回調(execProcess 之 cbStdout/cbStderr;execCli 之 onStdout/onStderr;execCliSession 之 onStdout/onStderr/onLine/onExit;execCliJsonRpc 之 onNotify/onServerRequest/onStderr 經 Session)一律經 `_callUser` 呼叫:拋錯時本套件之累積、切行、收尾 settle、喚醒 stop() 照常完成,錯誤以 `queueMicrotask` 原樣重拋(仍為未捕捉例外,文件契約不變;微任務先於呼叫端 await 之續行,無處理器時行程如修前以該錯誤結束,不因呼叫端隨即 `process.exit` 而遺失).此重拋為 R-PM-SETTLE-01 規則 2 之明文例外.
  6a.(2026-10-16 增訂,裁示 13 ⑦-1 P2)npm shim 已辨識而入口檔不存在者同規則 6 拋 ENOENT,訊息指入口路徑(`spawn <入口檔路徑> ENOENT`,errno/syscall/path 同 node 之形);限入口樣式位於 cmd-shim 之執行行(行首或 `&` 之後,可前置 `"%_prog%"` 與其參數,`"%dp0%\node_modules\…"` 之後只接 `%*`)者.入口樣式位於判斷句(如 `IF EXIST "%dp0%\node_modules\…"`)等非執行行者仍交 cmd.exe(自訂批次檔缺檔時走自己之退路,可正常執行;建議書原案以寬鬆樣式判定會誤殺此形).入口存在時之判定不變.
