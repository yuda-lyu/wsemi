## R-OBJ-ITER-01 迭代使用端傳入之物件:只依自有可列舉字串鍵,`length` 鍵不得使走訪改成陣列樣

- 依據: w-serv-orm 主責 agent 建議書《clearXSS 以 lodash each 遞迴巢狀物件》(2026-10-17,同型缺陷已於 w-serv-orm 以其 R-OBJ-01 修正);主控 2026-10-17 裁示 E1(clearXSS 修)、E2(其餘站點本次不改,列報告待裁示)、E3(本條入帳).
- 缺陷機制: lodash 的 `each/forEach/map/filter/reject/reduce/some/every/find/findLast/flatMap/groupBy/countBy/keyBy/partition/sortBy/orderBy/includes/size/toArray/sample/shuffle` 對「具非負整數 `length` 屬性(`isLength`: 0 ≤ 整數 ≤ 2^53-1)」之**任何**物件採陣列樣迭代: 只走索引 `0..length-1`、不走自有鍵.故 ①真實鍵被略過(其內字串不經處理); ②以 `o[k] = ...` 寫回時在物件上新增索引鍵; ③`length` 極大時迭代次數即其值,且逐一建立屬性(約 32 B/屬性),單一 JSON 請求即可使行程記憶體耗盡(實測 `--max-old-space-size=256` 下 `length` 為 1e8、`Number.MAX_SAFE_INTEGER`、4294967295 皆約 1 秒內 exit 134).不受影響: `Object.keys/values/entries`、`for...in`、lodash `keys/values/forOwn/forIn/mapValues/pickBy/omitBy/transform/cloneDeep/assign/isEqual/isEmpty`(對一般純物件;例外: 以**不可寫**之 `Symbol.toStringTag` 偽稱 `'Arguments'` 之物件會使 lodash `keys` 走索引,外審 sol F9,見候選 11)、一切對 `[object Array]` 之迭代.**`merge` 在同路徑一方為陣列、另一方為帶 `length` 之物件時受影響**(`isArrayLikeObject` 分支:目的端 `{ length }` 被當陣列,或來源端 `{ length }` 寫入目的陣列之 `Array#length`,見候選 6);物件對物件之 `merge` 不受影響.
- 規則:
  1. 迭代**使用端傳入(含 JSON、網路、檔案來源)之純物件**,只依其自有可列舉字串鍵(`Object.keys(o)`),`length` 與其他鍵同為一般鍵;不得以上列陣列樣函數迭代之.
  2. 真陣列(`Array.isArray` 為真)以索引迴圈迭代;`isarr`(依 `Object.prototype.toString`)為真而非真陣列者(以 `Symbol.toStringTag` 偽稱 `'Array'` 之物件)視為物件、以自有鍵迭代,不得依其 `length` 迭代(外審 F3,2026-10-17).
  3. 對物件之處理不新增、不刪除鍵(`length` 保持原值,其值若為物件或字串仍遞迴處理);成本(時間與記憶體)只依實際自有鍵數,與 `length` 之值無關.
  4. 契約本來就是陣列(`@param {Array}`)或內部自建之結構,不在本規則範圍;使用端對陣列參數傳入帶 `length` 之物件屬誤用.
  5. 把使用端物件深度合併者(ltdtmerge)不得用 lodash `merge`(其 `isArrayLikeObject` 判斷使目的端 `{ length }` 被當陣列、或來源端 `{ length }` 寫入目的陣列之 `Array#length`):自行遞迴,以 `Array.isArray` 與本地 `isPlain`(純物件=原型為 `Object.prototype`、null 或跨 realm 之原生 Object 原型,**判定不看 `Symbol.toStringTag`**,故不受不可寫之偽標籤影響;最外層資料列另放寬為任何非陣列物件,同 lodash `merge` 對最外層來源不論型別皆依自有與繼承之可列舉字串鍵合併)分流;目的端為輸入之複本(`copyDest`):**只複製陣列(保留空洞)與純物件,其餘值(類別實例、函數、Map、Set、Date、TypedArray、ArrayBuffer)取參照以保留同一性(含私有欄位)**,不就地改呼叫端輸入;類別實例(`isobj` 為真之非純物件)被當合併基底時寫入時複製(沿用原型、複製自有可列舉鍵);只讀目的端**自有鍵**之值(繼承而來之容器不併入,以自有屬性遮蔽,免得改到由原型共用之呼叫端容器);來源與目的端種類(陣列/純物件/其餘)不同時以來源為準(取代目的端,含目的端為 Date、Map 時);來源值為 undefined 時保留目的端既有值(目的端無該鍵時設為 undefined);新舊值 SameValueZero 相等(含 `-0` 與 `0`)時不重新賦值;來源為非純物件時直接取來源值(參照),TypedArray/Buffer 取複本;最外層來源列非陣列非物件(undefined、null、原始值)時忽略來源;`length` 於兩方向皆為一般鍵;來源之循環參照以 stack 對應已處理者、目的端之循環參照以 seen 保留;鍵 `__proto__` 以 defineProperty 設為自有屬性且讀取時不取原型(lodash 對值為物件之 `__proto__` 自有鍵靜默丟棄,此處改為保留為自有資料屬性),鍵 `constructor` 之目的端值為函數時視為不存在(同 lodash `safeGet`,防特殊鍵名誤用).
  6. 迭代外部封包(網路/檔案之 Uint8Array)內取得之長度/分塊資訊者(u8arr2obj 之 `sliceU8arr`)與還原二進位者(stru8arr2obj):迭代前先驗證 ①為真陣列(`Array.isArray`)、②各項為非負有限整數(`Number.isInteger` 且 ≥ 0)、③總量不逾封包資料區之長度、④分塊數量(扣除主區塊)乘 25 不得逾主區塊長度(每個二進位分塊在主區塊內至少有一個 25 位元組之標記字串,如 '[BlazeForUint8Array]::0' 連同 JSON 引號,故大量零長度/小分塊必被擋);任一不符即失敗回報(`{}`,或 `returnWithStateAndMsg` 時 `{ state: 'error', msg }`,msg 為 `invalid pks, <原因>`);⑤同一二進位索引只可被引用一次(stru8arr2obj,否則 `binary index referenced more than once[id]`;ArrayBuffer 標記每次引用都複製一份堆外記憶體,配置量=引用次數×分塊大小,`--max-old-space-size` 限不住).不依其內容配置記憶體或迭代.
