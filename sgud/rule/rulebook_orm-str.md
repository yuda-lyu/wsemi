## R-ORMSTR-01 w-orm 系列字串良構: 單一擁有者 `chkOrmStr` / `chkOrmData`、契約案例表 `_cvOrmStrCases`、只因良構性拒收

- 依據: dspec `w-orm系列條件語法支援盤點.md` 〈一之三〉9.(使用者 2026-10-20 裁示 D1「寫入資料之字串值與鍵名〔含巢狀物件與陣列元素〕全系列一律拒收孤立代理」、D2「主鍵亦拒收 NUL」、D4 只文件化;主控裁示 D3 `opt.url/db/cl` 建構時 throw、D5 無效主鍵統一照規格、D6 錯誤訊息不回顯、D7 共用函數歸 wsemi、D8 既有資料不遷移);系列審計 `dnow/20261020172106/agent-out/run01-系列審計回應.md`(§3.3 寫入值矩陣、§5.2 主鍵入口、§5.3 寫入值、§6.1 批 0、§10 dspec 草案;4883 格實測);主控複審 `review/run01-複審.md`;建議檔 `建議wsemi修正.md`(第 66 項批 0).
- 問題: UTF-8、BSON、msgpack 儲存把孤立代理碼元(UTF-16 代理對被拆開後只剩一半,`isWellFormed()` 為 false)改寫為 U+FFFD,使不同主鍵寫成同一鍵(覆蓋、誤刪)、文件鍵名撞鍵(無聲覆蓋另一欄)、寫入值與讀回值不同;條件側 `cvOrmFind` 已拒收,寫入側與主鍵入口原無共用判定(postgresql、mdb 各一份,另五個後端未檢核).
- 單一擁有者(皆純 JS、可隨 UMD 打包):
  - `src/chkOrmStr.mjs`: `chkOrmStr(s, opt)`(進 index)——單一字串之檢核,回 `null` 或固定原因字串.**全系列唯一**實作孤立代理與 NUL 判定之處.
  - `src/chkOrmData.mjs`: `chkOrmData(data, opt)`(進 index)——寫入資料之走訪(鍵名與字串值,含巢狀、陣列、Map/Set、Error/RegExp 之文字、繼承屬性),回 `null` 或 `{ reason, path }`;字串判定一律委派 `chkOrmStr`.
  - `src/_ormMsgClean.mjs`(內部): 訊息中鍵名之清除與限長;自 `cvOrmFind` 搬出,`cvOrmFind` 與 `chkOrmData` 共用(R-FIND-01 規則 12 之清除規則不變).
  - `src/_ormPathCut.mjs`(內部,2026-10-20 第 2 次執行新增): 錯誤訊息中路徑之尾端截斷(逾 120 碼元者截為 `...` 加末 100 碼元,切點避開代理對);`cvOrmFind` 與 `chkOrmData` 共用,**全系列唯一**實作路徑截斷之處(規則 16).
  - `src/_cvOrmStrCases.mjs`(內部,不進 index): 契約案例表(純資料加案例建構,`cases` 1553 案;2026-10-21 另增獨立匯出 `next` 9 案,見規則 17),各 w-orm-* 後端之測試以 `wsemi/src/_cvOrmStrCases.mjs` deep import,逐案對公開 API 執行.
  - `cvOrmFind.chkStr` 改呼叫 `chkOrmStr`(單一出處,行為不變;`cvOrmFind` 之 `R.nul0`/`R.lone` 刪除,原因詞彙取自 `chkOrmStr`).
- 規則:
  1. (STR-01) `chkOrmStr(s, opt)` 回傳 `null`(合格)|`'not a string'`|`'string contains NUL'`|`'string contains lone surrogate'`.**檢查順序固定: 非字串 → NUL → 孤立代理**(同時含 NUL 與孤立代理者回 NUL).非字串 = 任何非原始字串之值(含 `String` 包裝物件、`undefined`、`null`、數字、物件、Proxy),**不呼叫其任何方法**.U+FFFD、成對代理(emoji、CJK 擴充 B 區以後之罕用字)、最小/最大代理對、組合字元、ZWJ 序列、空字串、控制字元、零寬字元皆為良構(回 `null`);長度不限;對字串輸入不拋錯;不修改輸入.原因詞彙之單一出處為 `chkOrmStr.mjs` 之 `R` 表(內部,不匯出);案例表 `reasons` 與其值相同(測試核對).
  2. (STR-02) `opt.nul`(預設 `true`): **僅當 opt 有「自有資料屬性 `nul` 且值嚴格等於 `false`」時不檢 NUL**;繼承值、存取器(不被呼叫)、`Object.prototype.nul = false` 汙染、其他假值皆維持檢查.opt 可為 `undefined`、`null`、原始值、任意物件、凍結物件,不被修改.
  3. (STR-03) 純 JS 與內建於載入時取得: 不 import、不用 Node API、無 lodash;`getOwnPropertyDescriptor`、`hasOwnProperty`、`String.prototype.indexOf`、`isWellFormed`、`RegExp.prototype.exec` 皆於模組載入時取得,載入後被覆寫不影響結果;`isWellFormed` 只取 `String.prototype` 之**自有**成員,無此方法之環境走 `reLone` 正則退路;退路與原生對全部 2048 個代理碼元(單獨、首、中、尾、重複)與 1024 x 1024 個合法代理對(含其前後多一個孤立半邊)**逐一**核對一致(原生與退路各一個窮舉測試);無模組層可變狀態;`src/` 內無 BigInt 字面值(R-FIND-01 規則 15 之測試涵蓋);單一出處測試掃描 `src/` 凡程式碼出現 `isWellFormed`/`toWellFormed`/`codePointAt`/代理碼元字面值或十六進位範圍者須恰為已知之 5 個非驗證模組(案例資料 2、訊息清除、路徑切點、UTF-8 互轉)加擁有者.
  4. (DATA-01) `chkOrmData(data, opt)` 回傳 `null` 或**恰含 `reason`、`path` 兩鍵**之一般物件.`reason` 為 `chkOrmStr` 之原因: 預設只有 `'string contains lone surrogate'`;`opt.nul === true`(僅嚴格等於 `true`)時鍵名與字串值一併檢 NUL.**本函數只因良構性拒收,不引入其他拒收理由**(無深度/節點/長度/型別上限,不因函數值、BigInt、`undefined`、`NaN`、循環等拒收).作用於呼叫端**已複製**之物件(各後端於 `cloneDeep` 後、補主鍵與加欄位前呼叫,見規則 15)且假設後端其後**只使用同一份複本**;不改輸入(凍結之輸入亦可).
  5. (DATA-02) 走訪範圍: **一般物件與類別實例之自有可列舉字串鍵(鍵名與值)、繼承自 `Object.prototype` 以外原型之可列舉字串鍵(自有同名、較近原型同名者含不可列舉者遮蔽之)**、陣列元素(依索引)、**Map 之項目(字串鍵、物件鍵之內容、值;逐項迭代不預先具現)、Set 之元素**、`String` 包裝物件之字串值與額外屬性(字元索引鍵除外)、**`RegExp` 之 `source`、`Error` 之 `name`/`message`/`cause`**、**被後端自動轉成文字之函數(原始碼)與 Symbol 值(描述)**;Map/Set/RegExp/Error 另走訪其自有與繼承之可列舉屬性(取聯集).**存取器屬性(自有或繼承之可列舉者)呼叫其 getter 一次取值並檢核**(lodash `merge`、序列化皆會讀它;不可列舉之存取器不讀).盤點證據(2026-10-20,七個後端今日實際可存之型別,`tmp/inv/report.md`,探針實跑 lmdb、level、lowdb、reladb〔sqlite〕,序列化層實跑 mongodb、postgresql、mdb): ① **lmdb(msgpackr)原生存 Map(字串鍵、非字串鍵、物件鍵、巢狀)與 Set(存為陣列),孤立代理於其鍵/值/元素讀回為三個 U+FFFD,並存 Error 之 name/message 與 RegExp 之 source/flags**;② **mongodb(BSON)將 Map(字串鍵)存為子文件,孤立代理於其鍵/值改為 U+FFFD,非字串鍵 Map 於 `insert` reject,RegExp 存為 BSON RegExp**;③ level、lowdb、postgresql(JSON)將 Map、Set 存為 `{}`(內容丟棄),類別實例存自有可列舉屬性;④ postgresql、mdb 對函數(`fn.toString()`)與 Symbol(`Symbol(描述)`)以文字寫入,mdb 對 Error 為 `String(err)`、對陣列元素逗號串接寫入;reladb 文字欄拒、JSON 欄轉 JSON;⑤ **繼承可列舉屬性**: `insert` 路徑皆丟(但 `cloneDeep` 保留原型,實測見 `tmp/run01/probe-verify.mjs`),lmdb/level/lowdb 之 `save` 合併(lodash `merge` 走 `keysIn`)、reladb 之 `save` 更新(`md.update`)會存入,mdb 之 `get(data, k)` 經原型鏈取值;⑥ `cloneDeep` 保留原型與 `String` 包裝之額外屬性、巢狀 `Error`/函數以參照保留.故 Map/Set 內容、Error/RegExp 之文字、繼承屬性、函數/Symbol 文字皆有後端會存入,D1「一律」要求走訪;不存其內容之後端亦拒收(與 D1 一致,不分後端能力).**判型依內部槽(品牌方法),與 `Symbol.toStringTag` 無關**(標籤可被改寫、內部槽不能;原型為 `Object.prototype`/`null` 者直接當一般物件〔`cloneDeep` 亦視為一般物件而丟棄其項目〕;Error 優先以 `Error.isError`,跨領域可用);同一原型(如同一類別之多個實例)只做一次完整判型並記憶(其後以單一品牌方法確認,負記憶者直接當一般物件).
  6. (DATA-03) 略過(整個物件不走訪,連其上自有額外屬性也不看): `Date`、TypedArray(含 `Buffer`,以內建標籤 getter 判定)、`ArrayBuffer`、`SharedArrayBuffer`、`DataView`;原始值中之數字、布林、`null`、`undefined`、BigInt;Symbol 鍵、不可列舉鍵(含不可列舉之存取器,不讀)、陣列之洞與非索引屬性(`arr.extra`、`arr['01']`、`arr[2**32-1]`)、`Object.prototype` 上之屬性(汙染屬環境遭竄改,且 insert 不存)、`Number`/`Boolean` 包裝與 `Promise`/`WeakMap`/`WeakSet`(無可列舉內容).**不檢查**: `toJSON` 或自訂序列化之輸出(無法不執行呼叫端程式碼而得,已知限制 ①).
  7. (DATA-04) 走訪順序固定為文件順序(深度優先),回傳**首個**不合格處: 同一物件內**全部鍵名先於其值**(自有鍵名、由近至遠之繼承鍵名,再自有值、繼承值);值依自有鍵序(整數樣鍵依引擎規定先於其他鍵),陣列依索引,Map 依項目序(每項先鍵後值),Set 依元素序.批次由呼叫端逐文件呼叫,同批以最小索引之不合格文件為準;**同一文件主鍵先於資料**(主鍵由後端以 `chkOrmStr` 先檢).
  8. (DATA-05) 迭代走訪(顯式框架堆疊,不遞迴),**無深度、節點、寬度、字串長度上限**;循環參照與共享參照安全: 以 `WeakSet` 記錄已進入之容器,同一物件出現多處**只走訪一次**(路徑取首次出現處;60 層、2^60 展開之 DAG 毫秒完成);稀疏陣列依實際元素走訪,成本不隨 `length`(`length` 逾 4096 者改以自有鍵走訪,`length = 2^32-1` 亦毫秒完成);Map/Set 以迭代器逐項走訪(六十萬項、首項即不合格者在 64 MB 堆積內毫秒完成,先前版本預建全部路徑節點而 OOM).堆疊與路徑區段陣列為 null 原型、直接指派(不查找 `Array.prototype` 之索引 setter).內建於載入時取得(含 Map/Set 迭代器之 `next`、`String`;路徑截斷用之 `charCodeAt`/`slice` 在 `_ormPathCut`,規則 16),載入後被覆寫或 `Object.prototype`/`Array.prototype` 被汙染不影響結果.
  9. (DATA-06) `path`: 起始標籤預設 `'data'`(`opt.root`,僅自有資料屬性、為字串、非空、不逾 200 碼元、良構、不含 NUL/控制/格式/私用/孤立代理字元〔方括號為索引語法,不在此限〕者生效,其餘用預設);物件鍵 `.鍵名`(經 `_ormMsgClean`: 限 30 字元超過加 `...`,控制字元、格式字元、行/段分隔符、私用區、孤立代理、方括號以 `?` 取代)、陣列元素與 Set 元素 `[索引]`、Map 項目 `[序號]`(其鍵之內容為 `[序號].<key>…`;不合格之字串鍵為 `[序號].<key>`);Error/RegExp 之文字 `.message`、`.name`、`.cause`、`.source`;**不合格之物件鍵名本身不出現在 path,以 `.<invalid key>` 標示**;路徑超過 120 字元截為 `...` 加末 100 碼元(**切點落在代理對中間時往後移一碼元**,使訊息本身不含孤立代理;迭代組字串,路徑深度不限;截斷由 `_ormPathCut` 單一擁有,見規則 16).`path` 與 `reason` 皆良構、不含 NUL、不回顯值.
  10. (DATA-07) 不吞例外: 讀取過程中 Proxy 陷阱、getter 等拋出之例外原樣拋出(各後端於複製後呼叫則一般資料不會遇到);可重入;`opt` 之 `nul`、`root` 只讀自有資料屬性(描述子,存取器不被呼叫,繼承值與 `Object.prototype` 汙染不生效);`opt` 可為 `undefined`、`null`、原始值.

(ERR) 各後端以回傳值組成訊息,詞彙全系列一致,**不回顯值**: 主鍵 `invalid id: <reason> at [data[<k>].id]`、資料 `invalid data: <reason> at [<path>]`(後端以 `chkOrmData(doc, { root: 'data[<k>]' })` 取 path)、名稱 `invalid opt.<db|cl|url>: <reason>`(建構時同步 throw);單一物件呼叫之索引為 `data[0]`;處置形狀見 dspec 〈一之三〉9.3(`insert`/`insertBulk` 整批 reject 且不寫任何一筆、`save`/`del` 逐筆 `ok: 0` 附 `err`、`selectByPk` 回 `null`、GridFS 同理).
