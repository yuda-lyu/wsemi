## R-PORT-PIDS-01 查詢「誰在監聽某 TCP 埠」一律經 `execProcessPortPids`／`execProcessPortPidsSync`: 不依狀態欄、Windows 以 Get-NetTCPConnection 備援、失敗與無人嚴格分開

- 依據: 主控任務 20261030064553 run01(2026-10-30)之規劃;主控 `C:\opensrcOper\sgud\exp\experience.md` 第三十七節與重現腳本 `C:\opensrcOper\tools\repro-netstat.mjs`(Windows 11 build 26300.9818〔26H2〕＋KB5127936,兩台機器重現、重開機無效:`Get-NetTCPConnection` 對監聽中之 socket 回 State `0`〔無效值,應為 2〕,`netstat -ano` 因而整列漏列新起之監聽〔10 次 0 次列出〕,系統之 445 亦時有時無;`Get-NetTCPConnection -LocalPort <埠>` 10/10 查得正確之 OwningProcess、遠端埠 0).
- 單一擁有者: 內部模組 `src/_execPortPids.mjs`(不由 index 匯出;解析 `parseNetstat`、`parsePs`、`parseLsof`,子指令 `buildCmd`、`buildPsScript`,判定 `classify`,流程 `plan`〔generator,兩版共用〕,預設執行函數 `runCmd`〔非同步〕、`runCmdSync`,輸入 `readInput`,事件 `traceRun/traceResult/traceSettle`);對外 `src/execProcessPortPids.mjs`(Promise)與 `src/execProcessPortPidsSync.mjs`(同步,供 exit／signal 處理器).
- 規則:
  1. 監聽列＝TCP、本地埠相符(以最後一個冒號切出之埠字串完全相等,不用 endsWith)、遠端位址為萬用位址(`0.0.0.0`、`::`、`[::]`、`*`)且遠端埠為 0(或 `*`)、PID 為大於 0 之安全整數;**不依狀態欄**(狀態值可能錯、狀態文字隨語系、可能缺欄).netstat 之欄位取第 1 欄協定、第 2 欄本地、第 3 欄遠端、最後一欄 PID;本埠之監聽列而 PID 欄非數字者整份 netstat 輸出視為無法解析(轉查備援,不靜默略過而得部分結果).僅綁定未監聽(Bound)之 socket 無對端,亦列入(同樣佔用該埠,設計事實).
  2. Windows: 先 `%SystemRoot%\System32\netstat.exe -ano`(**不加 `-p TCP`**,只列 IPv4 會漏 `::` 監聽者),查到即採用;查無**或失敗**(無法啟動、逾時、離開碼非 0、無法解析)皆轉查 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive -EncodedCommand <腳本>`,腳本以 `Get-NetTCPConnection -LocalPort <埠>`(**不加 `-State`**、不輸出 State)只輸出本地埠、遠端位址、遠端埠、OwningProcess 之 ASCII 欄位,外包開始／結束標記,輸出用 `Write-Output`(`[Console]::Out.WriteLine` 於受限語言模式被擋);`%SystemRoot%` 於入口讀取一次,同一次查詢之兩個子指令用同一值(非同步版之第 2 個子指令於微任務後才組成);**其查無才判無人**、其失敗即整體失敗(netstat 之查無本即不採信,故 netstat 失敗不使整體失敗).`opt.useBoth` 為 true 時 netstat 有查到亦續查並取聯集,PowerShell 失敗即整體失敗(不以 netstat 之部分結果代替).
  3. PowerShell 腳本之錯誤分辨: 查無連線時 cmdlet 拋 `CmdletizationQuery_NotFound_LocalPort,Get-NetTCPConnection`(CategoryInfo 為 ObjectNotFound)→ 視為查無;**指令不存在之 `CommandNotFoundException` 之 Category 亦為 ObjectNotFound**,故以 FullyQualifiedErrorId 之前綴分辨,不以 Category;其餘錯誤輸出 `WSEMI-PORTPIDS-ERR <識別碼>` 並以離開碼 3 結束.
  4. Linux／macOS: `lsof -nP -iTCP:<埠> -sTCP:LISTEN -t`;離開碼 0 與 1(查無)為正常,其餘失敗;輸出含非數字字詞為無法解析.
  5. 失敗與無人嚴格分開: 空陣列只代表已確認無人;無法啟動(含指令不存在)、逾時、非預期之離開碼(含因訊號結束)、輸出無法解析(netstat 無任何 TCP/UDP 列、PowerShell 缺標記或標記間有不合格之列、lsof 非數字)、注入之執行函數拋錯／reject／回傳不合、埠號不合法、opt 不可讀 → 非同步版 reject 字串、同步版回 null(訊息經 onTrace 之 settle 事件 `msg`);兩版之訊息相同.
  6. 每個子指令帶時限(`opt.timeout`,預設 10000ms,非正數為預設,小數無條件進位為整數〔spawnSync 之 timeout 非整數即拋 ERR_OUT_OF_RANGE〕,夾至計時器上限)、`windowsHide: true`、不經 shell、stdin 不開啟;逾時或 stdout 逾 64MB 即強制結束子指令(SIGKILL;netstat 與 powershell 不另建子程序)並視為失敗(非截斷).同步版以 `spawnSync` 之 `timeout`/`killSignal`/`maxBuffer`.非同步版之預設執行函數: `error` 監聽先於存取 stdio;stdout/stderr 之串流 `error` 轉為失敗結果;一律先落定(done)再 kill(`child.kill` 失敗時 node 同步發出 `error`,其處理器見已落定即返回,不遞迴).
  7. 執行函數可注入(`opt.exec`,與 spawnSync 同形之 `{ status, stdout, error }`;非同步版可回 Promise;同步版回 Promise 視為失敗並先標記其 rejection 已處理).`opt.platform` 供測試走 lsof 路徑.
  8. 觀察回調(R-TRACE-01): 事件 `run`{src,timeout}、`result`{src,ok,reason,code,count}、`settle`{ok,reason,src,count,msg};兩版事件序列相同;opt 不可讀者不通知.
  9. 埠號支援字串型數字(`ispint` 且 ≤ 65535,`'0x50'`、`'1e2'`、`' 80 '` 等亦依 ispint 之 wsemi 慣例接受)與包裝物件(以 `Number.prototype.valueOf.call`／`String.prototype.valueOf.call` 拆包,不呼叫物件自身之 valueOf;R-WRAPPER-01);先取原始值快照再判定與轉換(判定之值即使用之值);其餘物件、Symbol、BigInt、已撤銷之 Proxy 為不合法.組進子指令之埠一律為 `Number()` 後之整數.
