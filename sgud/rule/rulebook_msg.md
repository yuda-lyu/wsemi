## R-MSG-V19-01 輸入無效之失敗訊息一律 `invalid <名稱>: must …`,不帶輸入值

- **規則**(dspec〈輸入參數之檢測機制〉§6 V19、V20):
  1. **格式**: 輸入無效之失敗訊息為 `invalid <名稱>: must <描述>`(英文、小寫開頭、固定詞彙;`must be`、`must contain`、`must not`、`must have` 皆可,優先 `must be`).名稱為**函數簽名之參數名**、`opt.<鍵>`、或帶實際索引之 `ltdt[1]`、`mat[0]`、`fps[3].path`、`data.binarys[0]`;已移除之鍵為 `invalid opt.<鍵>: removed, use opt.<新鍵>`.
  2. **不回顯輸入值**(V20): 訊息、reject 字串、`{ error }`／`{ err }`／`{ state: 'error', msg }` 之訊息與 `console` 輸出皆不含輸入值;比較類寫規則不寫數值(`invalid vstart: must be <= vend`、`invalid rmin: must be <= rmax`);位置以索引指出,對方以位置指出(`… (duplicated with ltdtOld[0])`).
  2b. **JSON 解析失敗**: `JSON.parse` 之 `SyntaxError` 訊息帶輸入片段(`Unexpected token … "<片段>" is not valid JSON`),一律改固定訊息(`j2o` `invalid v: must be a valid JSON text`、`str2obj` `invalid data: must be a valid JSON text`、`stru8arr2obj` `invalid data.results: must be a valid JSON text`、`u8arr2obj` `invalid u8a: must have chunk info that is a valid JSON text`、`fsReadJson` 之 `SyntaxError('invalid json: must be a valid JSON text')`);`o2j`／`obj2str` 之循環參照(V8 之訊息帶構造器名與屬性名)屬 C6 之原生錯誤,不在本批.
  3. **描述詞彙**(依該處實際之檢查函數,單一出處即本表): `isenum`→`a valid number`;`iseint`→`an integer`(帶範圍 `a positive integer`、`a non-negative integer`、`an integer from 1 to 65535`);`isestr`→`a non-empty string`;`isstr`→`a string`;`isfun`→`a function`;`isarr`→`an array`;`isearr`→`a non-empty array`;`isobj`→`an object`;`iseobj`→`a non-empty object`;`isblob`→`a Blob`;`isu8arr`→`a Uint8Array`;`isu16arr`→`a Uint16Array`;`isab`→`an ArrayBuffer`;`istime`→`a time string YYYY-MM-DDTHH:mm:ss`、`istimems`→`… .SSS`、`istimeTZ`／`istimemsTZ`→`… with a time zone (Z, +HH:mm or -HH:mm)`;元素 `<名>[i]`;列舉 `one of 'a', 'b'`;其餘以「應為何種」之短語.
  4. **只改訊息文字,不改行為**: 控制流程、錯誤型別、回傳形狀、通道(throw／reject／結果物件／狀態模式)、檢測條件與順序皆不動.本批唯一行為改變:`domIsStable` 之 `opt.timeDiff` 負數由「視為 0」改為依 K3 改用預設 100(0 仍有效;下游 w-component-vue 只轉傳鍵名、無站點傳 0 或負數).
  5. **範圍外(刻意不改)**: ①驗證器(C11)之終端使用者訊息: `isUserPw`、`isUserName`、`isUserIdentify`、`verifyValue` 之資料驗證文字(`verifyValue` 之 `type='custom'` 設定錯誤四則屬設定,已改);②w-orm 系共用詞彙(`cvOrmFind`、`lowerFind` 之 `invalid find: <原因> at [<路徑>]`、`chkOrmStr`、`chkOrmData`,與各 w-orm-* 後端之契約案例表共用,另案);③環境缺失(`no window`、`document is not available`、`invalid dayjs`、UMD 須以 script 載入)、操作失敗(逾時、spawn、檔案讀寫、`can not convert data`)、內部不變式(`invalid tLast`、`invalid colors array`)、狀態訊息(`cache` 之 `message` 事件之 `msg`;其 `error` 事件之 `invalid key` 為輸入無效,已改)、`時間已過`／`時間未到`(狀態結果,非輸入無效);④exec 家族 `<錯誤碼>: <使用端 getter 所拋之文字>`(R-EXEC-FAIL-01 規則 13,待裁示).
  6. **轉交前綴為合規形式**: 轉交下層訊息時前置來源函數名(`str2sha: invalid str: must …`、`u8arr2obj` 之 `stru8arr2obj: …`、`fsEnsureBins: invalid …`、console 之 `[wsemi debounce] invalid func: …`)視為合規(同 R-BIN-ENSURE-01 之範本);`fsGetBinManifestEntry` 之 reject 為 `Error: ` 加訊息(`fsErrMsg` 之既有形式,同函數其他訊息一致).
  7. **參數名更正**: fs 系 20 函數之 `pah` 更正為 `fp`(檔案類:`fsCreateFile(Core)`、`fsDeleteFile(Core)`、`fsDeleteFileSafe(Core)`、`fsExists(Core)`、`fsIsFile(Core)`)、`fd`(資料夾類:`fsCleanFolder(Core)`、`fsCreateFolder(Core)`、`fsDeleteFolder(Core)`、`fsDeleteFolderSafe(Core)`、`fsIsFolder(Core)`),`fsRenameFile(Core)` 之 `pahOld`／`pahNew` 為 `fpOld`／`fpNew`,`fsRenameFolder(Core)` 為 `fdOld`／`fdNew`;簽名、JSDoc `@param`、訊息之名稱一致(位置參數,無呼叫端影響).
  8. **下游相容**: 改訊息文字屬破壞性變更(破壞性變更第 77 項);下游以訊息字串比對者須隨升版調整(盤點見該項).
- **站點全集**: 逐函數舊→新對照見破壞性變更第 77 項(約 170 個對外函數:隨機範圍 10、數值計算 9、結構運算 14、Excel／CSV 7、外部程序與產生類 10、color、計時流程與 DOM 17、檔案系統與下載約 40、編碼／時間／blob／雙模式結構約 80).
- **盤點指令**: `node test/tools/…` 無;以測試為準: `npx mocha --no-parallel test/msgV19.test.mjs`(靜態防線 4 則 + 逐字斷言).Grep 輔助: `Grep "retError\('invalid [a-z0-9]+'\)" src/` 預期 0;`Grep "(Error|reject)\(['\`]invalid [^'\`:]*['\`]\)" src/`(排除 `invalid dayjs` 等內部)預期 0.
- **測試**: `test/msgV19.test.mjs`(靜態防線: ①無 `retError`／`reject`／`Error` 呼叫其訊息為 `invalid <名>` 而名稱後無 `: `、②`invalid <名>: ` 之後須接 `must `、③無 `<名> is not a(n) …` 舊式、④`getFile*Hash` 無回顯輸入之 console;逐字斷言: 編碼族 state 模式 60 餘案、時間 18 函數、blob 6 函數、手改函數〔`genDiagFunLog`、`fsGetBinManifestEntry`、`verifyValue`、`color`、`getFile*Hash`、`fsReadJson`、`fsSrlog`、`fsDeleteFile`／`fsRenameFile` 參數名〕);各函數既有測試檔之斷言已改為新訊息逐字;`test/jsdocFixes.test.mjs` 之 `@param` 與簽名一致由 20 函數擴為 src 全部對外函數;隨機範圍之採用邊界以 `test/tools/randBounds.mjs`(以 vstart <= vend 才不拋錯之性質驗證,取代由訊息取值)觀察.
- **已知限制**: ①`o2j`／`str2obj` 等 state 模式於內部例外(如 `JSON.stringify` 之循環參照)原樣轉出 `Error.toString()`(含屬性名),屬 C6 之「原生錯誤」處置,不在本批;②exec 家族 `<錯誤碼>: <文字>`(execCli 等輸入不可讀)、`execCliJsonRpc` 之 params 無法序列化訊息(含 method 名)維持(待裁示);③`fsEnsureBins` 之 `fsEnsureBins[<名>]:` 前綴與清單檔訊息為 R-BIN-ENSURE-01 之範本,未改;④`interp1` 之結果物件欄位 `ps`／`psEff`／`data` 仍回傳輸入值(欄位內容,非訊息,待裁示).

## R-READABLE-01 共用可讀性探針 `chkReadable`(排程第 558 項;單一擁有者 `src/chkReadable.mjs`)

- **規則**:
  1. **語意**: 近驗證器(C11,同 `chkOrmStr`): 可讀回 `''`,不可讀回**固定原因字串**(不含輸入值、不含原例外訊息);**永不拋錯**(任何輸入與任何 opt;opt 非物件、存取器、已撤銷之 Proxy 皆視為 `{}`,各鍵只讀一次且只採自有資料屬性);**不呼叫存取器與 `toJSON`**,不改寫受檢物(唯一可能執行使用端程式者為 Proxy 之陷阱與 `Symbol.toStringTag` 之存取器,即 `Object.prototype.toString` 之規格行為,與判斷函數同).純 JS;`Reflect` 之方法、`Object.prototype.toString`、`Array.isArray`、`WeakSet`／`WeakMap` 之方法與 `hasOwnProperty` 於載入時取得(載入後被覆寫不影響;陣列迭代等語言層面之機制不在保證內);無模組層可變狀態.
  2. **讀取範圍與判斷函數同源**: 預設只讀內部標籤(同 `isobj`／`isarr`／`isnull` 之前置讀取;原始值無可讀取者回 `''`);`opt.fun`(`isfun` 之讀取:`Symbol.toStringTag` 之 has 與描述子,不讀值、不暫時改寫);`opt.has`(`haskey` 之 `key in obj`,字串或 Symbol 鍵至多 1000 個);`opt.ownKeys`(`Reflect.ownKeys`;標籤為 `[object Object]` 者另沿原型鏈逐層讀自有鍵與字串鍵描述子,為 `iseobj` 之 for…in 讀取之超集,鏈超過 1000 層視為不可讀);`opt.elements`(`'first'` 同 `isearr`:讀 length,為 1 時讀第 0 個元素〔以描述子加取值讀取,對 Proxy 多觸發一次 `getOwnPropertyDescriptor`,為其超集〕;`'all'` 讀 length〔須為非負安全整數,超過 `opt.maxElements`(預設 1000000)回 `too many elements`〕並逐元素,洞與存取器元素略過);`opt.deep`(迭代堆疊不遞迴、WeakSet 去重,葉節點〔函數、型別陣列與 DataView、ArrayBuffer、SharedArrayBuffer、Error、DOMException、有 `toJSON` 者;依內部標籤判定,偽造 `Symbol.toStringTag` 者其子圖不被走訪,同序列化器〕不展開,陣列逐元素,其他物件取自有可列舉字串鍵之資料屬性值——**先取描述子、資料屬性再經 `Reflect.get` 取值**〔與序列化器經 `[[Get]]` 讀取同:Proxy 之 `get` 陷阱拋錯即不可讀,走訪取 `get` 之結果而非描述子之 `value`〕;讀取總量〔節點、陣列元素、物件鍵各計一次〕超過 `opt.maxReads`〔預設 50000000〕回 `structure is too large`,防止多個各自未逾 `maxElements` 之稀疏陣列或陷阱不斷產生新節點之圖使深探近乎無限).`fun`／`has`／`ownKeys`／`elements` 只作用於頂層之值.描述子之檢查一律用自有性(`hasOwnProperty`),不受 `Object.prototype` 汙染影響;`has` 之鍵收字串、Symbol、數字(同 `haskey` 轉為字串鍵).
  3. **原因詞彙**(固定): `tag is unreadable`、`function type is unreadable`、`key is unreadable`、`keys are unreadable`、`length is unreadable`、`length is not a non-negative safe integer`、`too many elements`、`element is unreadable`、`property is unreadable`、`structure is too large`、`unreadable`(保險).讀取順序: 標籤 → fun → has → ownKeys → elements → deep,先遇先回.
  4. **存取器不呼叫之後果**: 存取器屬性或元素之拋錯無從偵測(視為可讀,其後判斷函數回 `false`);此為 w-orm-level 原「`[0]` 元素 getter 拋錯以原錯誤失敗」之行為差異(見各庫改用時之對照).
- **站點全集**: 新增函數,下游站點 0;五庫之既有探針(w-dispatch-ai、w-converhp、w-orm-lowdb、w-orm-level、w-serv-webdata)由第 557 項等另行改用,本批不改五庫.
- **盤點指令**: `Grep "chkReadable" src/ test/` ; 語意差異表與各庫對照見主控任務之 `agent-out/ws492j-修正報告.md`〈探針〉.
- **測試**: `test/chkReadable.test.mjs`(`test/tools/hostileValues.mjs` 19 值 × 7 組選項之手寫期望、原始值與一般值 × 選項、opt 敵意值、has／fun／ownKeys／elements／deep 逐項、不呼叫存取器與 `toJSON` 之計數、全域汙染後不受影響;變異 29 項全擊殺;含獨立複審後補之深探經 `[[Get]]`、`maxReads`、自有性、數字鍵).
