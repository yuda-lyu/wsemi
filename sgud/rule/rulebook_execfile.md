# 規則帳本(結果走 JSON 檔之 CLI 執行與失敗摘要)

## R-EXEC-JSONFILE-01 結果走 JSON 檔之 CLI 執行一律經 `execCliJsonFile`;失敗摘要經 `execCliFailDetail`:失敗以結構化物件回報、必須參數缺漏 reject、半行不黏連、相對輸出路徑與子進程一致

- 單一擁有者: `src/execCliJsonFile.mjs`(`execCliJsonFile(opt) → Promise`;對外匯出;`execCli` 家族成員,建於 `execCli` 之上)、`src/execCliFailDetail.mjs`(`execCliFailDetail(result, n=300) → 字串`;對外匯出)、`src/_makeLineEmitter.mjs`(內部,不進 index,唯一使用端 `execCliJsonFile`).收錄依據 R-SCOPE-01 ②(`execCli` 家族加「結果走檔案」之變體)與 ①(`execCliFailDetail` 移動後有三個自有套件使用: `execCliJsonFile`、w-data-pipeline #39 `createLogger.cliFail`、w-knowledge-capture 經埠轉出;`execCliJsonFile` 之下游: w-knowledge-capture 與 tai-news-ai).來源: Gitea #41 §2、§5,主控 2026-11-01 裁定收.
- 規則:
  1. 約定: 腳本以 `[script, ...args, outputPath]` 之順序接收命令列參數(`outputPath` 恆為最後一個,原樣傳入),須於結束前將結果以 JSON 寫入 `outputPath`;成功回 `JSON.parse` 之結果原樣(不包裝,陣列/null/數字/字串皆可;腳本自行寫入之 `status` 鍵不被改寫).
  2. **失敗一律以結構化物件 `{ status: 'error', message }` 回報,不 reject**(呼叫端為允許個別失敗之迴圈): 子進程失敗(未啟動、逾時、非零離開碼、重試用盡)之 `message` = execCli 之 `error` 字串 + `execCliFailDetail(result)`;離開碼 0 而結果檔不存在/不可讀/非有效 JSON 為 `JSON parse failed: <訊息>`;`opt` 及其選項值不可讀(getter 拋錯、已撤銷 Proxy,輸入規格 K11)為 `<錯誤碼>: <訊息>`(同 R-EXEC-FAIL-01 規則 13,無碼者 `UNKNOWN`).
  3. 必須參數 `opt.script`、`opt.outputPath`: 缺漏或非**非空原始字串**(不收 `String` 包裝物件:傳給 spawn 與檔案路徑者)**reject** `Error('execCliJsonFile 需要 script')`／`Error('execCliJsonFile 需要 outputPath')`(回傳 Promise 者以 reject 回報,輸入規格 §5.1;`async function`,不同步拋),**先於任何子進程啟動**;`opt` 非物件/陣列/函數視為 `{}`(進而報缺 `script`).
  4. 其餘 opt 鍵非預期輸入視為未給(K3): `args` 非陣列→`[]`(取快照)、`exe` 非空原始字串否則 `'node'`、`progressPrefix` 非字串→`''`、`onProgress`／`onTrace` 非函數→不用;`timeoutMs`／`cwd`／`maxRetries`／`retryDelayMs` 原樣交 `execCli` 判型(其自行改用預設).`retryDelayMs` 透傳為主控 2026-11-01 准許之順手補強(原 srcRunner 版不轉傳).
  5. `onProgress(line, isErr)`: stdout 與 stderr **各建一份**行切分器(共用緩衝會互相插隊)、**每行先 `trim()`(去前後空白,含行尾 `\r`、NBSP、全形空白)才處理: trim 後為空者(空行、純空白行)不回報,前綴比對與回報皆用 trim 後之字串**(已依原契約: srcRunner `core/util/runJsonCli.mjs:47-68` 之 `makeLineEmitter`〔`ln.trim()`〕;原測試 `test/unit-check-util.test.mjs:60-71`、`test/unit-runner.test.mjs:320-322`)、`progressPrefix` 非空時只回(trim 後)以其開頭之行(兩流皆套;縮排之前綴行亦收,回報時已去縮排;前綴自身含前導空白者永不符);**某次嘗試之殘留無換行半行於該次嘗試定案(`settle` 事件)時補回報**(同受 trim 規則),不延到下一次嘗試、不與其第一段輸出黏成一行(建議檔未載之補強,主控 2026-11-01 裁定維持,見已知限制);回調拋錯之處置同 `execCli` 之 `onStdout`(R-EXEC-FAIL-01 規則 12: 不影響累積與結果,原樣重拋為未捕捉例外),切行器於一段內有多行時先回報全部行再重拋第一個錯誤.
  6. **相對 `outputPath` 以子進程之工作目錄為基準**(`opt.cwd`,未給為本進程工作目錄)讀回,與腳本寫入位置一致(審查實測原讀本進程工作目錄,`cwd` 不同則讀不到或讀到舊檔).
  7. `onTrace` 原樣轉交 `execCli`(事件同其 JSDoc: attempt/retry/spawn/data/full/timeout/kill/settle/done);R-TRACE-01 之測試同步點.
  8. `execCliFailDetail(result, n=300)`: 讀 `result.attempts`(**非負整數含 0 即顯示**,非整數視為無〔輸入規格 K3〕)與 `result.stderr`(字串才採用),輸出 `，共試 N 次 → stderr`(兩者皆有時逐字同建議檔之格式);stderr 內連續空白/換行壓成單一空格後**委派 wsemi `strTruncate(s, n)` 取前 `n` 字,超長補 `...`、未超長原樣**(與原契約同一函數;`n` 以 UTF-16 碼元計,落在代理對中間時會切成半個字元,同 `strTruncate`);僅有次數為 `，共試 N 次`(`attempts` 為 0 亦然: `，共試 0 次`)、僅有 stderr 為 ` → stderr`、皆無為 `''`(**已依原契約**: srcRunner `core/util/misc.mjs:55-59` 之 `cliFailDetail`〔`attempts != null` 即顯示,`oneline(stderr, n)`〕;原測試 `test/unit-runner.test.mjs:67-69`〔`，共試 1 次`〕、`test/unit-util.test.mjs:115-117`〔` → only stderr`、`...`〕、`unit-runner.test.mjs:377`〔`caller.mjs:96` 零供應商之結果 `attempts` 為 0〕);`result` 非物件或不可讀為 `''`;`n` 非預期(非正整數)用 300(此項保留,原契約為不截斷);永不拋錯;只讀 `attempts`、`stderr` 兩欄(不回顯其他欄位)。
