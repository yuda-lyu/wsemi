## R-DL-VERIFY-01 下載執行檔或二進位資產一律經 `fsDownloadFileVerify` 驗證 SHA-256(與大小)

- 依據: 主控任務 20261028054319 第 148 項前半(wsemi-run01,2026-10-28): w-mousekey(`src/binEnsure.mjs`)、w-dwload-dlp(`src/downloadFiles.mjs`)各自實作下載後驗證,w-ffmpeg 完全不驗;改由 wsemi 單一出處提供.規格為兩個參考實作之行為聯集(對照見該輪報告〈與參考實作之對照〉).
- 單一擁有者: `src/fsDownloadFileVerifyCore.mjs`;對外包裝 `src/fsDownloadFileVerify.mjs` 只傳入 Node 內建 fs、crypto、Readable、pipeline 並展開使用者 opt(opt 不可讀時交 Core 以 E_ARG reject).
- 規則:
  1. 自有套件下載**會被執行、載入或解壓使用之檔案**(執行檔、壓縮檔與其分片、腳本等)一律經 `fsDownloadFileVerify`;期望值為釘提交時寫死之 `{ sha256, size }`,或每次嘗試前重取清單之期望值函數.不得以 `fsDownloadFile` 或自寫 fetch 下載後直接使用;`fsDownloadFile` 只用於不需驗證之一般檔案.
  2. 正式檔名只以「驗證通過之暫存檔更名」寫入: 入口(同步、首個 await 之前)建立所在資料夾(已存在者不呼叫 mkdirSync——Windows 對磁碟根 `C:\` 以 recursive 建立回 EPERM,實測)並以 `realpathSync` 固定正式檔之絕對路徑(之後工作路徑改變不影響;所在資料夾以最後一個分隔符自行切分,保留 UNC 前綴,Windows 之磁碟相對路徑 `C:a.bin` 之資料夾為 `C:`,不可把冒號留在檔名而成替代資料流;不用 `getPathParent`;**分隔符依平台: Windows 為 `/` 與 `\`,其他系統只有 `/`(反斜線為合法檔名字元,結尾反斜線亦是檔名而非資料夾)**,`realpathSync` 結果結尾有無分隔符之判斷同依平台(非 Windows 只認 `/`;資料夾實名結尾為反斜線者如 `dir\` 不得被當成分隔符而重組成同層另一檔,run03 外審 H5 實測屬實);**檔名為空、`.`、`..`,或 Windows 下含冒號者於下載前即 E_ARG(不發請求、不建任何檔)**——run02 增訂,原會下載完才於更名失敗,冒號者並會留下名為冒號前段之空檔(NTFS 替代資料流之本體));暫存檔與正式檔同資料夾、名稱 `<絕對路徑>.<pid>.<亂數12碼>.part`、以 `openSync(…, 'wx')` **同步排他建立,建立成功才屬於本次**(EEXIST 與其他開檔失敗皆非本次之檔,不刪);寫入串流以該 fd 建立(建立拋錯時先 closeSync);任何失敗路徑不寫正式檔名(舊檔原樣);每次嘗試後以 unlinkSync 清除本次建立之暫存檔(ENOENT 視為已清;EPERM/EBUSY/EACCES 至多 3 次);**本次更名成功後暫存名不再屬於本次,不再依名稱刪除**;刪不掉者記入 `leftovers` 與 `cleanupError` 並寫入訊息,不稱已清除;成功而先前嘗試有殘留者於結果之 `leftovers` 帶出.
  3. 驗證對象為 fetch 依 content-encoding 解碼後之位元組(fetch 不支援之編碼則為原始位元組;所存內容恆等於期望雜湊所描述之位元組);串流計算 SHA-256 與大小,寫入關閉後**重讀暫存檔**核對雜湊與大小,不符(寫入後被改動)即 E_HASH_MISMATCH 不更名.給 size 時: 未經內容編碼且無 transfer-encoding 之 content-length 與 size 不符即不建立暫存檔(E_SIZE_MISMATCH)、內容超過 size 即中止、**正常結束**而短少為 E_SIZE_MISMATCH,**傳輸中斷**造成之短少為 E_NETWORK(兩者預設皆可重試);sha256 比對前正規化為小寫;size 為 undefined 或 null 視為未給,給了須為非負安全整數或**十進位整數字串**(前後空白可;小數、指數、十六進位、帶正負號、超過安全整數之字串一律 E_ARG——run03 起,原以 `isp0int` 接受 `'0.999…9'`〔得 1〕、`'1e-324'`〔得 0〕等轉數字後失真之形).
  4. 拒絕值為 Error 物件,`code` 為穩定列舉 E_ARG、E_EXPECTED、E_HTTP、E_NETWORK、E_TIMEOUT、E_TIMEOUT_TOTAL、E_SIZE_MISMATCH、E_HASH_MISMATCH、E_FS、E_RENAME(新增須記於本條變更紀錄),另帶 step(argument、prepare、expected、request、download、verify、rename)、attempts、url、fp、expected、actual、leftovers、cleanupError、status(E_HTTP)、cause;訊息含失敗步驟、第幾次/共幾次、預期與實際(雜湊截 16 碼)、hint 與 `note: file[…] was not modified by this call`.參數錯誤(E_ARG)只帶 code、step、attempts(0)、cause.**此為 R-FS-REJECT-01 規則 1(拒絕值字串)之刻意例外**(派工規格明定錯誤物件,下游依 code 處置).
  5. 可重試: E_NETWORK、E_TIMEOUT、E_HTTP 之 500~599/408/429(600 以上不重試,run03)、E_HASH_MISMATCH 與 E_SIZE_MISMATCH(`retryOnMismatch:false` 可關)、E_EXPECTED 且期望值函數所拋錯誤 `retryable === true`;其餘(其他 HTTP 狀態、E_ARG、E_FS、E_RENAME、E_TIMEOUT_TOTAL、期望值函數回傳無效值)不重試.錯誤之歸屬以**最先出錯之一端**判定(寫入端最先者為 E_FS,不論有無 syscall;來源端最先者為 E_NETWORK);**本函數自建之錯誤以身分判定(`mkErr` 登記於模組內 WeakSet),不以 `code` 判定**(run03 外審 H7、H8: 傳入之 fs getter、fetch、串流所拋值即使帶 `E_NETWORK`、`E_FS` 等同名 code 亦是外部錯誤——fs getter 拋出者 E_ARG、fetch 拋出者 E_NETWORK〔可重試〕、先出錯之寫入端 E_FS);**某一端先出錯即停止停滯與整體計時**(其後關閉較慢時晚到之計時中止不得取代先出錯之一端,H9;若傳入之 pipeline 仍不落定,5 秒後以不帶原因之 abort 使 guard 落定,不寫入中止原因);使用全域 fetch 時網址須可由 `new URL` 解析且為 http 或 https **且不得帶帳密(含只有使用者名稱或只有密碼者)**(否則 E_ARG,不視為可重試之網路錯誤;需認證時傳入自訂 fetch;傳入 fetch 者協定不限;`opt.fetch` 給了卻不是函數者 E_ARG,只有 undefined/null 才用全域 fetch,H16;回應本體不是 WHATWG ReadableStream〔如 Node Readable〕者 E_ARG、step download、不重試,P5);**錯誤訊息與錯誤物件之 `url` 一律遮蔽網址內之帳密(`scheme://***@host`)**(run02 增訂,原帶帳密之網址被全域 fetch 拒收而當成可重試之網路錯誤重試 3 次,且帳密原樣落入訊息;run03 外審 H6 擴大: 遮蔽涵蓋訊息內**任何出現處**〔前有空白之網址、底層錯誤文字帶回之網址〕,最終訊息整段經 `maskUrl`;`cause` 仍為原始錯誤物件,含未遮蔽之網址).本體寫完(pipeline 完成)即停止停滯與整體計時,之後之等待(寫入端關閉至多 5 秒〔除 `close` 事件外同時輪詢 `closed` 屬性,`emitClose:false` 之串流亦可判定,H11;關閉逾時後失敗清理不再重複等待,H10〕、重讀以剩餘整體時間為上限)各自設限,其錯誤不得被計時器之中止原因取代(重讀時之磁碟錯誤為 E_FS 不重試).放棄等待後才落定之回應(傳入之 fetch 不響應中止)於落定時取消其本體.第 n 次重試前等待 `retryDelayMs*n`,等待會超過整體上限即停止並註明 `retry stopped`.整體上限以 `performance.now` 計,涵蓋取期望值、網路、寫入暫存檔與重讀核對;**每個等待點皆以計時器自行落定**(fetch 與 pipeline 以 guard 與中止競速、讀檔以計時競速、丟棄回應本體不等待 cancel),不依賴所傳入之 fetch 或串流是否響應中止;請求結束(含失敗)時中止該請求以釋放未讀完之本體與連線.更名與清理不計入: 退避至多約 3 秒,更名失敗時比對正式檔之讀取每次至多 `stallMs`.停滯為連續 `stallMs` 未收到資料(含等待標頭),每收到資料重新計時.
  6. 更名: EPERM/EBUSY/EACCES 時最多共嘗試 5 次(間隔 `min(retryDelayMs,200)*i`);每次失敗後正式檔若已為期望內容(大小與 SHA-256 相符)即成功;其他錯誤碼不重試.
  7. 併發共用: 同程序內鍵為正式檔之絕對路徑(win32 小寫),每鍵可有多個進行中之工作;同網址、同期望值(靜態比 sha256 與 size、函數比同一參照)、同一 `opt.fs`、`opt.crypto`、`opt.Readable`、`opt.pipeline` 與 `opt.fetch`、入口所取出之各原始方法之身分(同一模組物件於兩次呼叫之間被換了方法者不共用,H13)、同樣之 maxAttempts、retryOnMismatch、useSkipIfMatch 者共用同一工作,共用者得同一結果物件或錯誤物件(fp 為最先呼叫者所給之字串),等待以各自之 totalMs 為上限(逾時 E_TIMEOUT_TOTAL、step `share`、attempts 0,訊息註明共用之下載續行且之後仍可能更新正式檔);stallMs、retryDelayMs、onRetry 依最先呼叫者.不符者各自下載(同一正式檔之期望值不同時,最後完成更名者為最終內容);`useShare:false` 不共用;落定後即自表移除.
  8. 期望值函數收到 `{ attempt, signal }`,以剩餘整體時間為上限(逾時 E_TIMEOUT_TOTAL 並 abort signal);拋錯為 E_EXPECTED(cause 為所拋值).`onRetry` 之拋錯與 rejection 皆忽略.
  9. 數值選項經 `_optNum`(數字字串可、無效用預設、計時器毫秒夾至 2^31-1);布林選項經 `isbol`;預設 maxAttempts 3、retryDelayMs 1000、stallMs 30000、totalMs 600000、retryOnMismatch true、useShare true、useSkipIfMatch false.所傳入之 fs、crypto、Readable、pipeline 之方法於入口一次取出並綁定(取出時拋錯為 E_ARG),之後不再讀取 opt(檢查之值即使用之值).**呼叫端傳入之函數(期望值函數、fetch、pipeline、onRetry)一律不帶接收者呼叫(`this` 為 undefined)**,不把內部脈絡(含 `fpAbs`)交給呼叫端(run02 增訂,原以 `ctx.fn(...)` 呼叫而使 `this.fpAbs = …` 可使驗證後更名至他處);**傳入之 fs 所拋值之 `code` 一律經 `codeOf`(getter 拋錯視為無 code)讀取**,不讓原錯誤漏出而繞過 code/step/leftovers 之回報(run02 增訂: 更名、刪暫存、開檔三站點;與 `buildCtx` 之 `isOwnErr` 同類);**包裝物件(`new String`、`new Number`、`new Boolean`)於入口解包為原始值**(`unwrap`: 以 `String/Number/Boolean.prototype.valueOf.call` 取內部槽,不呼叫物件自身可被覆寫之方法): urlIn、fpOut、期望值之 sha256 與 size、布林選項(`new Boolean(false)` 原為 truthy)皆然,其後之檢查、切分、請求、更名只用解包後之值——檢查之值即使用之值(run03 外審 H1、H2、H4、H14,實測原先可使「呼叫端給的雜湊 A,以另一雜湊 B 驗證並發布」「檢查後再切分而更名到另一檔」).
  10. 計時器(停滯、整體、期望值逾時、讀檔逾時、共用等待)於各自之等待結束時清除,呼叫落定後不撐住行程.
