## R-BIN-ENSURE-01 外部執行檔之取得一律經 `fsEnsureBins`(清單校驗、快取→鏡像→GitHub、離線)

- 依據: 制式規格 `C:\opensrcOper\dspec\外部執行檔之存放下載校驗與離線.md`(使用者 2026-10-28 裁示;以下「規格」皆指此檔,條號 S/M/D/O/E/T 為其條號)§6;主控任務 20261028054319 之 wsemi-run04.**規格為上游真理源,本條只記 wsemi 實作須長成什麼樣與其站點**;規格與本條不一致時以規格為準並回報主控(規格之矛盾與遺漏見該輪報告〈規格回饋〉).
- 單一擁有者: `src/fsEnsureBinsCore.mjs`(清單檢核、取得順序、快取校驗、鏡像、離線、主幹清單、解壓與組合、併發共用、錯誤);對外 `src/fsEnsureBins.mjs` 只傳入 Node 內建 fs、path、crypto、Readable、pipeline、child_process.spawn 與 `process.env`;下載(含本地鏡像之複製)一律經 `fsDownloadFileVerifyCore`(R-DL-VERIFY-01).清單項產生器 `src/fsGetBinManifestEntry.mjs`(規格 M1,供各套件 `toolg/genBinManifest.mjs`).
- 規則:
  1. 清單 schema 1 一律經 `normManifest` 檢核,不符為 E_MANIFEST(帶 `field`,遮蔽帳密),**檢核失敗時不發任何請求、不建任何資料夾**;不認得之鍵(各層)、型別不符一律拒收;**字串一律須為原始字串**(`new String`、帶 `Symbol.toPrimitive` 之物件拒收: 其每次轉換可回不同值,terra H1 實測可使檢核通過之成員在 tar 參數變為 `-P` 而解出到暫存夾外);每個欄位只讀取一次,之後只用轉換後之值.名稱與相對路徑之白名單單一出處為 `src/_binRules.mjs`(`isBinName`、`isBinRel`,`fsGetBinManifestEntry` 共用): `name` 與分割檔名 `^[A-Za-z0-9_](?:[A-Za-z0-9._+-]{0,198}[A-Za-z0-9_+-])?$` 且非 Windows 保留裝置名、`path`/`member`/`manifestPath` 為 `/` 分隔之相對路徑每段同檔名規則但中間可有空白(無空段、`.`、`..`、反斜線、glob 字元);`pkg` `^[a-z0-9][a-z0-9._-]{0,213}$`、`repo` `<owner>/<name>`、`commit` 40 碼小寫十六進位(釘選模式有 `path` 之檔時必填)、`url` 須 https、不得帶帳密、**路徑整段解碼後**(含 `%2F`)不分大小寫不得含 `/releases/latest`,亦不得指向分支(`refs/heads`、`raw.githubusercontent.com/<o>/<r>/{master,main,HEAD}/`、`github.com/<o>/<r>/{raw,blob}/{master,main,HEAD}/`)、`sha256` 64 碼十六進位(轉小寫)、`size` 非負安全整數(數值).`parts` 須同時有 `assembled` 與 `extract`,頂層不得有 `path`/`url`/`sha256`/`size`;名稱不分大小寫不得重複.
  2. 取得順序(規格 O2): ①快取 `<快取>/<最終 sha256>/<name>`(快取資料夾: `opt.cacheDir`〔'' 為預設〕> `<W_BIN_CACHE>/<pkg>` > `<pkgRoot>/bin-cache`);命中須為一般檔案且大小與 SHA-256 皆符合**本次清單**(規格 D4);本行程內以「檔案識別 `dev:ino:size:mtimeMs:ctimeMs`＋期望 sha256 與 size」記憶,皆相同才不重複雜湊;**雜湊後再確認識別未變**(雜湊期間被換掉者重新檢查,至多 3 次;仍變動則不採用不刪除,交後續取得);**取得並放入後不記入記憶**(放入後至記錄前可能被換掉,terra H4),下次使用時校驗一次;不符(含符號連結)者識別未變才刪除,刪不掉為 E_FS(step cache,不續以缺檔或成功回報),識別已變(他方換上新檔)則重新檢查;資料夾為 E_FS 不刪.②鏡像(`opt.mirror` > `W_BIN_MIRROR`;'' 為不使用)`<鏡像>/<pkg>/<sha256>/<name>`,本地資料夾以「讀檔之 fetch」交 Verify(同一套暫存、校驗、原子更名),http(s) 直接交 Verify(**離線時不追隨重導**,重導即拒用);404/410 為無此檔,鏡像端之失敗(含不符)為拒用並記原因、續找下一來源;**寫入端之磁碟錯誤(Verify 之 E_FS、E_RENAME)不是鏡像之問題,直接拒絕不續找**.③GitHub `https://raw.githubusercontent.com/<repo>/<commit 或 master>/<path>` 或廠商 `url`.**任何來源之內容皆以清單校驗後才落在快取路徑**.
  3. 離線(`opt.offline`〔須原始布林〕> `W_BIN_OFFLINE` 為 `1`/`true` 不分大小寫): 不連 GitHub 與廠商網址、不取主幹清單,只用快取與鏡像(http 鏡像為允許之內網來源,不追隨其重導);缺檔者彙整為單一 E_OFFLINE_MISSING(`missing[]` 每項 name、sha256、size、cachePath、mirrorPath、url、member、archive、parts、reasons;訊息列名稱、完整 sha256、大小、快取與鏡像之完整路徑〔未設鏡像時為 `<W_BIN_MIRROR>/<pkg>/<sha256>/<name>`〕、來源網址、鏡像拒用原因與準備方法).
  4. 壓縮檔(規格 D5): 於 `<快取>/.work-<pid>-<亂數>`(排他建立)取得壓縮檔或各分割(各自校驗大小與雜湊)→ 分割依序串接後校驗 `assembled` → 以 tar 解出單一成員(Windows 為 `<SystemRoot>\System32\tar.exe`,不經 PATH;他系統 `bsdtar` 再 `tar`;**參數一律為暫存夾內之相對 ASCII 路徑、成員前加 `--`,工作目錄設為暫存夾**,避開非 ASCII 絕對路徑經命令列傳遞;時限同 `opt.totalMs`,逾時終止後等其結束至多 5 秒才清理)→ 解出檔須為一般檔案且符合 `extract` 之大小與 SHA-256 → 原子更名移入快取(占用時至多 5 次;失敗而最終檔已是期望內容視為成功)→ 刪除暫存夾(刪不掉者列入結果之不可列舉屬性 `leftovers` 與進度通知,不稱已清除).快取只存最終檔(不存壓縮檔與分割檔);鏡像查找先找最終檔再找壓縮檔(`<name>` 為其 path/url 之最後一段)或各分割.
  5. 主幹模式(規格 M5、T8): 取 `opt.floatingManifestUrl`(https、不帶帳密;**改變信任錨,只供測試或套件作者,範本 ensureBins 不轉傳**)或 `https://raw.githubusercontent.com/<repo>/master/<manifestPath 預設 bin/manifest.json>`(上限 1 MB,時限同 `opt.stallMs`,逾時或失敗時取消未讀完之本體),同樣 schema 檢核且須同 pkg 與 repo;成功時副本存 `<快取>/manifest-last.json`(排他開檔寫入後原子更名,失敗刪除暫存檔;**只作紀錄,不作為校驗依據**);失敗(含離線、無效、他套件)時用基準清單(**不用該副本**: 其可信度同快取夾,terra H5 實測可偽造副本使竄改之快取檔通過).
  6. 錯誤(規格 E3): 一律 reject 帶 `code` 之 Error,**為 R-FS-REJECT-01 規則 1 之刻意例外**(同 R-DL-VERIFY-01).code: E_ARG、E_MANIFEST、E_OFFLINE_MISSING、E_EXTRACT(本實作增列,見報告〈規格回饋〉)、E_RENAME、E_FS 與 Verify 之 code(訊息前綴 `fsEnsureBins[<pkg>] file[<name>] from <github|url|mirror>`,另帶 `pkg`、`bin`、`source`);屬某檔之錯誤皆帶 `step`、`pkg`、`bin`,傳入元件所拋無 code 之值轉為 E_FS.訊息、`field`、`missing`、進度事件、解壓程式之輸出內之網址帳密一律遮蔽(`cause` 保留原始錯誤,同 R-DL-VERIFY-01 已知限制⑲);鏡像網址帶帳密而未給 `opt.fetch` 為 E_ARG.
  7. 併發: 同程序內同一最終檔、同來源設定(清單項、pkg、快取與鏡像位置、離線、下載與時限選項、所傳入 fs/fetch/spawn/crypto/Readable/pipeline 之身分)之呼叫共用同一次取得,落定後自表移除;跨程序以 Verify 之暫存檔與原子更名、解出檔之原子更名保證不讀到半檔.
  8. 參數(規格 E1): `pkgRoot` 必填(原始字串);給了之選項須為正確型別(否則 E_ARG,不發請求不建夾);環境變數只由本函數讀取(`opt.env`,對外函數為 `process.env`);進度通知 `onProgress` 不帶接收者呼叫,拋錯與 rejection 皆忽略.

(第 2 輪外審後增訂)網址規則單一出處 `_binRules.mjs` 之 `binUrlProblem`(`fsGetBinManifestEntry` 共用): 分支只就 GitHub 原始檔網址之 ref 欄位判定(`master`、`main`、`HEAD`、`refs/heads/…`),版本標籤下載網址之標籤名可含 `refs/heads`;雜湊後之 lstat 若為不存在以外之錯誤為 E_FS(不當成換檔),多次檢查仍持續變動亦為 E_FS(不當成缺檔);解壓程式被終止後之 `error` 事件不提早回傳(續等 `close` 或等待上限),等待上限後仍未確認結束則**保留暫存夾**並列入 leftovers;同步寫入之回傳值非正整數即拋錯(不無限迴圈);`opt.floatingManifestUrl` 只能在 `https://raw.githubusercontent.com/<repo>/` 之下(同一 repo;否則 E_ARG,不發請求);取主幹清單逾時勝出而回應已落定者亦取消其本體(恰一次);本函數自建之錯誤訊息於建立時即遮蔽帳密(`mkErr`),傳入元件所拋值一律包裝(以模組內 WeakSet 判定是否為 `tagErr` 標註之下載核心錯誤,不以 `pkg`/`code` 判定);入口一併檢核下載核心所需之 fs 方法(`realpathSync`、`createWriteStream`、`statSync`)與 `Readable.fromWeb`/`from`,鏡像取得時下載核心之 E_ARG 直接拒絕;leftovers 為「每次取得」之陣列,共用者共享,失敗時附於錯誤之 `leftovers`,並含下載核心回報之刪不掉之暫存檔與主幹清單副本之暫存檔;共用判定另比解壓程式(`tarProgs`)與所取出之各方法身分.
