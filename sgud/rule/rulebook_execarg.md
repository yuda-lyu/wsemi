# 規則帳本(執行外部程序三函數之輸入檢測)

本檔收 `execProcess`(`prog`、`args`、`opt.codeCmd`)、`execProcessKillPid`(`pid`)、`execJsCode`(`fpJsCode`、`opt`)之輸入檢測與其訊息(2026-11-18,ws492f,主控任務 20261116102625,排程第 492 項第 5 批:外部程序).索引見 `sgud/rule/rulebook.md`〈索引〉;`execProcess` 之原生錯誤固定詞彙另見 `rulebook_exec.md` R-EXEC-FAIL-01 規則 15.

## R-EXEC-ARG-01 外部程序三函數之輸入檢測:必須參數先於任何程序之建立或殺程序、不轉型、訊息固定且不回顯值

- **依據**: 輸入規格 `C:\opensrcOper\dspec\輸入參數之檢測機制.md` K1(種類由程式碼宣告)、K2(必須參數)、K3(opt 鍵非預期視為未給)、K4(檢測之值即使用之值)、K5(不互轉)、K6(安全整數)、K7(數字字串)、K9/V20(訊息不回顯輸入值)、V8(轉傳之鍵由下游檢)、V17(檢測先於副作用)、V19(訊息格式)、§5.1(Promise 者 reject,不同步拋)、§11(安全相關 fail-closed);盤點報告 `wsinv-審計報告.md` 〈不符清單〉`execProcess`、`execProcessKillPid`、`execJsCode` 三列與 W-05;專案原則 14(不做舊版相容).
- **原缺陷(2026-11-18 以子行程「攔截替身」於 HEAD 實測,替身阻擋、未真的建立程序或殺程序)**:
  - `execProcessKillPid` 以 `Number()` 轉型後交 `tree-kill`:`null`、`''`、`' '`、`0`、`-0`、`[]` 皆得 pid 0(Windows 為 `taskkill /pid 0 /T /F`,POSIX 為 `kill(0)` 殺本行程群組),`-1` 照交(POSIX `kill(-1)` 殺所有可殺之程序),`true` 得 1,`'0x10'` 得 16,`1.5` 經 `parseInt` 得 1,`4294967294` 經 int 轉換環繞為 -2(POSIX 殺行程群組);39 種無效形中 **29 種於修前會呼叫 tree-kill**;訊息回顯原值(`pid[abc] kill failed: pid must be a number`).
  - `execProcess` 之 `prog`:spawn／execFile 模式由 node 拒收(原生訊息),**exec 模式 `quote()` 內 `String()` 把 `undefined`、`null`、物件、數字轉成字串當指令,空字串 `''` 時 `args[0]` 成為被執行之指令**(`execProcess('', ['x'], { mode: 'exec' })` 執行 `x`);95 格(19 種無效 prog × 5 模式組合)中 **91 格於修前會建立程序**、args 無效 145 格中 89 格;`args` 元素 `undefined`／`null`／`true`／物件被 node 轉成 `'undefined'`／`'null'`／`'true'`／`'[object Object]'` 照常傳給程式;原生錯誤與引號訊息回顯 prog;`codeCmd` 不支援時 reject 並回顯標籤.
  - `execJsCode`:`fpJsCode` 非字串之 reject 為 node 原生訊息並回顯值,空字串與 NUL 與「檔案不存在」不分;default 非函數之訊息帶出路徑;載入之 Node 原生錯誤(`ERR_MODULE_NOT_FOUND`)訊息帶出路徑.
- **規則**:
  1. **`execProcess.prog`(三種模式一致)**: 必須參數,須為非空之原始字串且不含 NUL(單一擁有者 `src/_chkFsPath.mjs`,與 R-FS-INVALID-PATH-01 同源),不轉型——`undefined`、`null`、數字、布林、物件、陣列、函數、`Symbol`、`BigInt`、包裝字串(`new String`)、空字串、含 NUL 皆無效;訊息 `invalid prog: must be a non-empty string`／`invalid prog: must not contain a NUL character`;spawn 模式 prog 以引號起頭或結尾(原 `prog[<值>] of spawn does not need to add quotes`)改 `invalid prog: must not start or end with a quote in spawn mode`(exec、execFile 模式不檢引號,同舊).**先於任何子程序之建立**(V17;含 `codeCmd` 為 `'auto'`／`'system'` 時取系統字碼頁之 `chcp`),reject 不同步拋(§5.1),onTrace 之 `settle` 之 `reason` 為 `'prog'`.
  2. **`execProcess.args`**: 容器須為真陣列(`Array.isArray`;**不用 `isarr`**——其以 `Object.prototype.toString` 判定,帶 `Symbol.toStringTag: 'Array'` 之偽陣列物件會以空參數放行)或原始字串(可空;空陣列與空字串代表無參數);陣列元素須為**字串(不含 NUL,可為空字串)或有限數字**(數字轉為十進位字串後使用,K4);`undefined`、`null`、布林、物件、陣列、函數、`NaN`、`±Infinity`、`BigInt`、包裝字串皆無效;字串型 args 不含 NUL.稀疏陣列之洞(`undefined`)無效;判型、`length`、元素讀取拋錯(已撤銷之 Proxy、getter)視同型別不符;每個元素只讀一次並以快照使用(`args = list`).訊息 `invalid args: must be an array or a string`／`invalid args: must not contain a NUL character`／`invalid args[<i>]: must be a string or a valid number`／`invalid args[<i>]: must not contain a NUL character`(`<i>` 為索引,不含值);先於任何子程序之建立;`reason` 為 `'args'`.
  3. **檢測順序**: `opt` 不可讀(取回調前之失敗,`opt is not readable: <訊息>`)→ `prog` → `args`;`opt` 之 `mode`、`cbStdout`、`cbStderr`、`useChcp`、`timeout`、`cwd`、`onTrace` 之 K3 處置不變.
  4. **`execProcess.opt.codeCmd`(K3)**: 有效字串但不支援之編碼(非 TextDecoder 標籤、非字碼頁編號、非 `'system'`／`'auto'`)與非有效字串一律視為未給,改用預設 `'utf8'`,**不再於執行前 reject**(原 `codeCmd[<標籤>] is not a supported encoding`,回顯標籤;原設計理由「用錯編碼靜默產生亂碼」已由使用者 2026-10-31 之 K3 原則取代);`opt.debug === true` 時經 `opt.funLog`(或 `console.warn`)警告一次:`[wsemi execProcess] invalid opt.codeCmd: must be a supported encoding label, 'system' or 'auto', using default 'utf8'`(固定詞彙,不含標籤;去重表與 `_numOpt` 共用).onTrace 之 `settle` 之 `reason` `'codeCmd'` 已移除.
  5. **`execProcess` 訊息不回顯值(V20)**: 檢測訊息見規則 1、2;帶錯誤碼之 Node 原生錯誤(同步拋錯、`'error'` 事件、`opt is not readable`)之 message 改固定詞彙 `operation failed (code X)`(`spawn[ENOENT]:\noperation failed (code ENOENT)`),實作見 `rulebook_exec.md` R-EXEC-FAIL-01 規則 15(`execSpawnError` 之 `opt.fixed`);不可達之 `invalid mode[<值>]` 改 `invalid opt.mode: must be one of 'spawn', 'exec', 'execFile'`(死碼,只改訊息、不刪).**例外(刻意保留)**: `cwd is not an existing folder: <cwd>`(R-EXEC-FAIL-01 規則 7;使用端 w-data-mseed 之測試比對含 cwd 之整句,見〈待裁示〉);子程序自身之輸出(`code[N]:\n輸出`,exec 模式之 shell 會回顯找不到之指令名);`opt is not readable` 內呼叫端自拋且無錯誤碼之文字.
  6. **`execProcessKillPid.pid`**: 必須參數,須為 1~2147483647 之整數,或其十進位數字字串(去頭尾空白;`iseint(v, { use: 'int32', min: 1 })` 判定,轉換後之數字才交 tree-kill,K4;`' 12 '` → 12、`'4.2e5'` → 420000、`'1.0'` → 1);**`0`、負數、`-0`、小數、`'0x10'`／`'0o7'`、尾綴雜字、`''`、`' '`、`null`、`undefined`、布林、陣列(含 `[5]`)、物件(含 `valueOf`)、`NaN`、`±Infinity`、`BigInt`、`Symbol`、包裝物件、超出範圍(`2147483648`、`4294967294`、`2**53`、`1e21`)皆無效**,reject 固定訊息 `invalid pid: must be an integer from 1 to 2147483647`(不含 pid 之值),**先於任何殺程序之動作**(安全相關,dspec §11 fail-closed:POSIX `kill(0)`／`kill(-1)`／環繞之負值為殺行程群組或全部可殺之程序);不同步拋.上限為 `pid_t` 之範圍(大於其者經 int 轉換環繞為負).殺程序失敗仍為 `pid[N] kill failed: <訊息>`(`N` 為轉換後之數字;tree-kill 之訊息於 Windows 為 taskkill 之系統字碼頁輸出,不在本規則保證內).onTrace: pid 無效只發一次 `fail`(`{ pid: null, msg: <整句固定訊息> }`),**不發 `start`**(`start` 為「即將呼叫 tree-kill」);有效者 `start`／`done`／`fail` 之 `pid` 恆為數字.
  7. **`execJsCode.fpJsCode`**: 必須參數,非空之原始字串且不含 NUL(同規則 1,`chkFsPath`),無效 reject `Error('invalid fpJsCode: must be a non-empty string')`／`'invalid fpJsCode: must not contain a NUL character'`(不含路徑之值;async 函數,reject 不同步拋;reject 值維持 `Error` 物件,同其既有之失敗型式),**先於載入任何檔案**;路徑不是既存之檔案(不存在、資料夾,跟隨連結)reject `'invalid fpJsCode: must be an existing file'`(與「參數無效」分開,文字不同);目標檔之 default 匯出不是函數 reject `'invalid fpJsCode: must be a module whose default export is a function'`(原 `the default export of [<路徑>] is not a function`,回顯路徑);載入目標檔時之 Node 原生錯誤(帶錯誤碼且碼為 `ERR_` 起頭之 Node 內部碼,或帶 `syscall` 之系統錯誤〔如目標檔頂層讀檔之 `ENOENT`〕者;如目標檔所依賴之套件不存在之 `ERR_MODULE_NOT_FOUND`,原 message 帶出目標檔路徑與套件名)改新建之 `Error`,message `operation failed (code ERR_MODULE_NOT_FOUND)`、保留 `code`(`_fsErrMsg` 之 `fsErrSan`,W-23 作法;判定函數為 `execJsCode.mjs` 內之 `isNodeNativeErr`);其餘(無錯誤碼者如目標檔之 `SyntaxError`;目標檔頂層求值時自拋之自訂碼如 `'ECONFIG'` 之錯誤,獨立複審提出,不被固定詞彙取代)原樣;**目標函數內部拋出之錯誤原樣向外傳遞**(不經本函數處置,含其 `code` 與 message).
  8. **`execJsCode.opt`(W-05 建議 B、V8)**: 整份原樣交給目標 default 函數(同一個物件,不複製、不檢測、不改寫),逐鍵由目標函數自行處置;只有 `undefined` 取預設 `{}`,`null`、字串、數字、陣列照舊原樣傳入;JSDoc 已載明.
- **測試**: `test/execProcess.test.mjs`〈execProcess prog與args之輸入檢測(R-EXEC-ARG-01)〉(新增 15 案)與其內既有案之更新;`test/execProcessKillPid.test.mjs`〈pid之輸入檢測(R-EXEC-ARG-01)〉(新增 5 案)與既有案更新;`test/execJsCode.test.mjs`〈execJsCode fpJsCode之輸入檢測與opt直通(R-EXEC-ARG-01)〉(新增 6 案)與既有案更新;`test/_execSpawnError.test.mjs`〈execSpawnError opt.fixed(R-EXEC-FAIL-01之15)〉(6 案);子行程執行器 **`test/tools/execArgGuardRunner.mjs`**(`procBad` 95 格、`argsBad` 145 格、`procQuote` 30 格、`procOk` 15 格陽性對照、`stubControl` 8 個替身之陽性對照、`killBad` 39 格、`killOk` 9 格陽性對照).**驗法**: 該執行器於獨立子行程以「攔截替身」取代 `child_process` 之 `spawn`、`exec`、`execFile`、`spawnSync`、`execSync`、`execFileSync`、`fork` 與 `process.kill`(替身一律不呼叫真實函數,故任何輸入——含修前之碼、含 pid 0 與負數——皆不可能真的建立程序或殺程序;須於替身掛上後才載入被測模組,因 `tree-kill` 於載入時即取走 `spawn`、`exec`),「先於任何程序之建立或殺程序」以攔截記錄為空判定(不是看結果字串),並以有效輸入之陽性對照證明替身確實計到呼叫;真的殺程序之案只對測試自己啟動之子進程,且修前亦不含 0、負數、`null`、`''`、`[]`、BigInt 等於修前會被 `Number()` 轉成真實 pid 之值.指令: `npx mocha --no-parallel test/execProcess.test.mjs test/execProcessKillPid.test.mjs test/execJsCode.test.mjs test/_execSpawnError.test.mjs --timeout 180000`.
