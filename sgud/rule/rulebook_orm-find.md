## R-FIND-01 w-orm 系列條件(find)之形狀檢核: 單一擁有者 `cvOrmFind`、白名單、fail-closed、檢查之值即使用之值

- 依據: dspec `w-orm系列條件語法支援盤點.md` 〈一之一〉(使用者 2026-10-16 裁示 B: 不給條件為全部,傳了非條件物件 reject)、〈一之三〉(使用者 2026-10-17 裁示白名單;6. 細節為主控 2026-10-17 複審定案);方案 `dnow/20261017093849/agent-out/run01-審計與方案.md` §3(WL 規則)、§4.4(函數規格)、§7(契約案例表);主控複審 `review/run01-複審.md`(D1 放 wsemi、D2~D6 採建議、D8 錯誤格式).
- 單一擁有者: `src/cvOrmFind.mjs`(`cvOrmFind(find, opt)`,進 index、隨 UMD 打包);契約案例表(純資料)`src/_cvOrmFindCases.mjs`(內部模組不進 index,各 w-orm-* 套件之測試以 `wsemi/src/_cvOrmFindCases.mjs` deep import,逐案對公開 `select`/`delAll` 執行).
- **不含**(留在各後端,不得搬入本函數): 欄位型別檢核、欄名是否存在於 model/表、主鍵正規化、DATE 範圍、`$..$` 欄引用、`Infinity` 欄名(mongo-sql 之 `+key>=0` 誤判)、63 bytes 識別字上限等後端專屬值限制、NULL 三值語意與分族(`$ne`/`$nin` 遇 NULL: MongoDB 式與 SQL 式維持分族,屬設計)、任何轉譯、level 與 lowdb 將 find 內 Date 轉 ISO 字串.
- 規則(WL 代號沿用方案 §3;每條對應一組斷言):
  1. (WL-01) 頂層: 未給、`undefined`、一般物件 `{}`(含 null 原型)為全部,回傳空的 null 原型物件(每次全新,不回傳輸入本身).
  2. (WL-02、WL-H1) 頂層與每層條件物件須為一般物件(原型為 `Object.prototype` 或 `null`,內部標籤為 `[object Object]`,且非 TypedArray);`null`、陣列(含 `[]`、`[{…}]`)、字串、數值、布林、函數、Date、RegExp、Map、Set、Promise、Error、Buffer、類別實例、原型上帶條件之物件、`String`/`Number` 包裝物件、BigInt、Symbol 一律 reject,不得視同 `{}`.**原型被改為 `null` 或 `Object.prototype` 之內建物件**(Map、Set、WeakMap、WeakSet、Promise、ArrayBuffer、SharedArrayBuffer、DataView、TypedArray、Symbol 與 BigInt 包裝、WeakRef、FinalizationRegistry;其標籤取自原型之 `Symbol.toStringTag`,原型一改 `Object.prototype.toString` 即回 `[object Object]`)於**任何位置**(頂層、欄位運算子物件、`$and`/`$or` 元素,不論空或帶自有鍵;Proxy 包住者無法穿透,依規則 16 之窄處置)亦 reject: TypedArray 以內建標籤 getter(對非 TypedArray 回 undefined、不拋錯)於**每個**物件列舉自有鍵之前檢查(其自有索引鍵與元素數成正比,先列舉會耗盡記憶體),其餘品牌於走訪完畢後一次檢查(作法、成本、Proxy 之處置與對合法輸入之影響見規則 16).
  3. (WL-03、WL-S1、WL-S2) 欄位直接等值 `{欄: 純量|null}`,多欄隱含 AND.純量 = 字串、有限數字(含 `-0`)、布林、有效 Date;BigInt、Buffer、NaN、±Infinity、無效 Date、包裝物件、陣列、物件、函數、Symbol、RegExp、`undefined` 一律 reject;字串不得含 NUL 與孤立代理字元(長度不另限; 判定與原因詞彙自 2026-10-20 起由 `chkOrmStr` 單一擁有,見 R-ORMSTR-01).Date 以內部槽判定(不受 `Symbol.toStringTag`、`instanceof`、被覆寫之 `getTime`、子類別、null 原型、跨 realm 影響,所有純量位置一致),輸出為新 Date.
  4. (WL-04、WL-N1、WL-E5) 欄位運算子物件: 僅 `$eq $ne $gt $gte $lt $lte $in $nin`;`$eq`/`$ne` 之值為純量或 `null`,`$gt $gte $lt $lte` 之值為非 null 純量;須至少一個運算子(`{欄:{}}` reject);非 `$` 開頭之鍵(巢狀條件、一般鍵與運算子混用)與白名單外之 `$` 鍵 reject;同欄多運算子為 AND 允許.
  5. (WL-05、WL-E1、WL-E2、WL-N1、WL-L3) `$in`/`$nin`: 值為純量陣列,元素不收 `null`、`undefined`、非純量,長度 ≤ `maxIn`(預設 10000);`$in:[]` 允許(恆假,不得因空而變全部);`$nin:[]` reject(恆真);元素重複允許.
  6. (WL-06、WL-E3、WL-E4、WL-L2) `$and`/`$or`: 值為非空陣列,元素為**非空**條件物件(`{}` reject),長度 ≤ `maxList`(預設 1000);可巢狀、可與欄位鍵並列(並列為 AND)、一個條件物件可同時有 `$and` 與 `$or`;`$and:[]`、`$or:[]`、元素為 `{}`、非陣列、元素非物件 reject.
  7. (WL-07) 白名單外一律 reject(整批性、不得靜默忽略): 文件層 `$` 鍵(`$not $nor $where $expr $text $comment $jsonSchema $custom $function` 與任何未知者)、欄位層之 `$and $or $not $nor $regex $options $exists $type $mod $elemMatch $size $all $like $ilike $null $notNull $equals $bitsAllSet` 等、Symbol 鍵(含 sequelize `Op`)、函數值、子查詢、RegExp 值、陣列等值、巢狀物件等值.
  8. (WL-F1、WL-F2、WL-L4) 欄名: 字串,長度 1~`maxKey`(預設 128,以 UTF-16 碼元計),符合 `^[\p{L}_][\p{L}\p{M}\p{N}_]*$`,禁 `__proto__`;點路徑、`$` 開頭、連字號、空白、引號、`->`、`::`、數字開頭、空字串一律 reject.`constructor`、`toString`、`length`、`prototype`、`hasOwnProperty`、`Infinity` 等符合文法者共用層**不擋**(欄是否存在與後端專屬限制屬各後端轉譯層);欄名區分大小寫.
  9. (WL-L1~L4、opt) 上限: 邏輯巢狀深度 `maxDepth`=32(`$and/$or` 之層數,頂層條件物件為第 0 層,第 32 層接受、第 33 層 reject;循環參照以此拒收;`$or` 與 `$and` 同計)、`$and/$or` 長度 `maxList`=1000、`$in/$nin` 長度 `maxIn`=10000、節點總數 `maxNodes`=100000(條件物件、運算子物件、純量各計 1,`$in/$nin/$and/$or` 之陣列本身不計;防共享參照造成之指數展開,超過即停止走訪)、欄名 `maxKey`=128.`opt` 只可**下調**:給大於預設者以預設為準;不提供放寬運算子或欄名之開關.`opt` 須為物件、`null` 或未給;自有鍵須皆為上列五個之一(Symbol 鍵與不可列舉之未知鍵亦屬未知);五個值以**屬性描述子**讀取(只認自有資料屬性,繼承值不生效,存取器 reject 且不被呼叫),值須為正整數(`undefined` 視為未給);違反者同步拋 `invalid opt: <原因>`(程式設定錯誤,與 find 無關,先於 find 檢核).
  10. (WL-H2、WL-H3) 異常結構: 以 `Reflect.ownKeys` 走訪,Symbol 鍵、不可列舉鍵、存取器屬性 reject;陣列須為真陣列(`Array.isArray`)之密集純索引(無洞、元素可列舉且非存取器),`length` 只讀一次且須為非負整數,先比對上限再走訪(`length` 極大者不配置、不迭代),元素逐一以屬性描述子讀取一次;元素皆讀畢後,陣列之自有鍵須**逐鍵**皆為 `length` 或小於 n 之標準索引字串(不得帶其他自有屬性含 Symbol 鍵、`'01'`、`'-0'` 等;不以鍵數比對,以免 `ownKeys` 回報之額外鍵因另一鍵被省略而湊成相同數量).不使用 lodash 或任何陣列樣迭代(R-OBJ-ITER-01): 帶 `length` 鍵之一般物件(如 `{length:3}`)為一般欄名.
  11. (WL-H4) 檢查之值即使用之值: 輸出為**全新深複本**——所有物件為 null 原型、陣列為全新密集陣列、Date 為新 Date,與輸入無任何共用參照;以 `defineProperty` 與 null 原型描述子建立屬性,不受 `Object.prototype`(含 `get`/`set`/`value` 與可列舉屬性)、`Array.prototype`(含索引 setter)汙染影響;每個屬性與元素於**每次走訪到時**只讀一次並只用該次所讀之值(**共享參照: 同一物件出現於多處時每出現一次即各讀、各檢、各複製、節點各計,不以快取去重——快取會使輸出與後端走訪之展開成本不一致,且節點預算即靠逐次計入防指數展開**);凍結之輸入亦可;不修改輸入.檢核與訊息所用之內建(Object、Reflect、Array、Date、Number、WeakSet、`String.prototype` 之 `indexOf`/`charCodeAt`/`slice`/`isWellFormed`、`RegExp.prototype.exec`)於模組載入時取得,載入後被覆寫不影響檢核與訊息;`isWellFormed` 只取 `String.prototype` 之自有成員(無此方法之環境走 `reLone` 退路,不經原型鏈取得 `Object.prototype` 同名成員).
  12. (WL-H5、WL-R1、D8) 錯誤: 一律同步 `throw new Error('invalid find: <原因> at [<路徑>]')`;**不回顯值**(原因只用固定詞彙,路徑只含 `find`、鍵名、`[索引]`;顯示之內部標籤限固定名單,自訂標籤一律為 `object`;鍵名限 30 字元並以 `?` 取代控制字元(Cc)、格式字元(Cf,含雙向控制與零寬字元)、行與段分隔符、私用區、孤立代理與方括號,使鍵名不致偽造路徑段;路徑超過 120 字元截為 `...` 加末 100 字元;整段訊息有上限);走訪中任何例外(呼叫端 getter、Proxy trap、`Symbol.toStringTag` getter、已撤銷之 Proxy、拋出非 Error 之值、拋出自稱 `invalid find` 或與內部失敗物件同形(`{reason}`)之物件)一律轉為此格式,原因為固定詞 `an exception was thrown while reading the condition`、路徑為例外當下之位置(**包含組訊息時讀取內部標籤所生之例外**,不吞掉改報他因;**屬性描述子讀取(`getOwnPropertyDescriptor` 陷阱)與元素描述子讀取之例外,路徑含該屬性鍵或元素索引**,如 `find.g`、`find.$in[1]`,不止於所屬物件;存取器與不可列舉之屬性亦報至該屬性鍵(`accessor property is not allowed at [find.g]`),與元素之既有作法一致;Symbol 鍵無法安全顯示、陣列洞無屬性鍵,仍報所屬物件/陣列之路徑),**不轉述呼叫端之錯誤訊息、不重拋呼叫端之錯誤物件**;可重入(呼叫端之 trap 內再呼叫本函數,內外層之節點預算與路徑互不影響,無模組層可變狀態).原因詞彙之單一出處為 `src/cvOrmFind.mjs` 之 `R` 表(內部,不匯出);案例表之 `why` 為各 REJ 案應含之詞彙.
  13. 純 JS: 不 import 任何外部模組(2026-10-20 起唯一例外: import `chkOrmStr.mjs`、`_ormMsgClean.mjs`、`_ormPathCut.mjs`〔2026-10-20 第 2 次執行新增〕三個同為純 JS 之內部模組,見 R-ORMSTR-01 規則 13、16)、不用 Node API(`Buffer`、`process`、`require`)、不用 lodash(`structuredClone` 為 Web 標準全域而非 Node API,僅於載入時功能偵測並自檢,缺少或不符則走精確探針,見規則 16),可隨各套件 UMD 打包(測試於無 Node 全域之 `vm` 環境載入執行;另以 `w-package-tools` 之 `rollupFile`(babel、壓縮)打成 UMD 於 `vm` 實跑,2026-10-17,產物 7549 位元組).
  14. 各 w-orm-* 套件接線約定(供批 1~2,wsemi 不強制): 入口於 `isClosed` 判定之後、任何讀取/連線/刪除之前呼叫 `cvOrmFind`,其後 `select` 與 `delAll` 只用回傳之複本(檢核失敗為整批性錯誤,先 `emitError` 再 reject);結果無自有鍵者走「全部」分支;level、lowdb 於自身轉譯層將複本內 Date 轉為 ISO 字串;w-orm-mdb 傳 `{ maxIn: 2000 }`;**使用 SQLite 之後端(reladb、mdb)建議傳 `maxList: 999`**(實測 SQLite 對平鋪 `a OR b OR …` 之表達式樹深度上限為 1000: 999 項可執行、恰 1000 項得 `Expression tree is too large (maximum depth 1000)`,為 DB 錯誤而非 `invalid find`;`$and` 同;方案 §3.5 稱 1000「對齊 SQLite」須修正為 999);w-orm-postgresql 之第二階段另須擋 `Infinity` 欄名(mongo-sql 以 `+key>=0` 判為陣列索引而丟失欄名)、63 bytes 識別字、`$..$` 欄引用字串、`$nin` 表名改寫守門;SQL 後端之欄位/型別/存在性檢核屬各自第二階段;各套件測試逐案執行案例表(`ids.mongo`/`ids.sql` 依族別,`schema:true` 者 SQL 族可 reject 或回 `ids.sql`,`need` 者依後端上限判定).

(發布約束,2026-10-17 第 2 次執行) **`src/` 內程式碼位置不得有 BigInt 字面值(`1n`、`0xffn` 等)**,需要 BigInt 值寫 `BigInt(1)`: 發布時 `script.txt` 第 4 列 `jsdoc -c .jsdoc`(只掃 `src/`)以 jsdoc 4.0.5 之 estree 剖析,把 BigInt 字面值讀成真 BigInt 再 `JSON.stringify`(`node_modules/jsdoc/lib/jsdoc/src/astnode.js` 之 `BigIntLiteral` 回傳 `node.value`),拋 `TypeError: Do not know how to serialize a BigInt` 而使文件產製與發布中止;jsdoc 之 `-X` 模式不會觸發,須以實際設定產文件才會.註解與字串內之文字不受影響.案例表之 4 處(T19 E12 I21 V11)已改 `BigInt(n)`(案例表 `find()` 於執行期才建值,行為不變);`test/` 不受 jsdoc 掃描,測試檔仍可用字面值(`cvOrmFind.test.mjs` 保留).檢查: `test/_srcBigIntLiteral.test.mjs`(以 jsdoc 同一剖析器 `@babel/parser` 之 estree 外掛取 AST,找 `Literal` 且 `value` 為 bigint 者,不以正規式去註解;含掃描器自測: 程式碼位置須被找到、註解/字串/樣板字串/`BigInt()` 呼叫不得被誤報;掃 `src/` 全部 `.mjs` 與 `.js`,剖析失敗亦視為失敗),工具 `test/tools/bigintLiteralScan.mjs`.
  16. (外審補強,2026-10-17 wsemi 第 1 次執行;來源: 下游 w-orm-lmdb/level/lowdb 批 1 外審 sol F1、opus F4 之 `verify-sol.mjs` 證據)**內建品牌物件於任何位置一律 reject,與 Proxy 之處置**:
